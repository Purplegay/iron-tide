# 苏军第一关《时空转移》工程师空投刷屏

## 根因与原图依据

玩家截图显示供电阶段大量运输机和降落伞。旧脚本在接管时光机时立即派首架十人飞机；之后每 0.4 秒检查是否存在己方 `SENGINEER`。工程师要等飞机到投放点才实际生成，所以场上无工程师时，每次扫描都会再发一架六人飞机，直至首名工程师出现。

复核零售 Steam `mapsmd03.mix` 的 `SOV01UMD.MAP`，本机先前提取文件 `%TEMP%/IronTide-S01-retail/sov01.map` 哈希为 `498b989a4b6f579dee0904a77f1fabf982c14786db21a46c41900fc8344ec72b`。`Destroy_Time Defenses` 启用 `Sell_Time Defenses`（3），再启用 `Reinforce_10 Engineers`（25，团队 `0957AE2C`）。`Detect_Engineers Dead`（`0DD0203C`）启用 `Reinforce_6 Engineers`（3，团队 `093D0EFC`）；六人事件触发时自禁用。两个团队分别载 10 和 6 人，共用检测标签与 `DK`（114）航点；`SP3.2_Audio_EnoughPower` 禁用两条空投触发器。

## 实际改动及玩家结果

- `scripts/world/time_shift.gd::tick` 在进入供电阶段时初始化首批发送标记；退出供电控制（开始穿越或失败）后不再调用增援逻辑。
- `scripts/world/time_shift_events.gd::engineer_reinforcements` 使用本项目任务时钟，接管时光机约 28 秒后在 114 号航点派一架十人飞机。空投中仍有待投人员，或已有己方工程师（包括伞降中），均阻止新派补援。全部失去后约 3 秒派一架六人飞机；运输机被毁且无人存活时可再补。任务扫描粒度约 0.4 秒。两条计时不依赖现实时间。
- 首发、补援计时用既有战役状态保存，在途载荷用既有单位 `special`。旧版供电阶段存档没有首发标记，按已安排首发处理（旧逻辑进入阶段已尝试发送），继续依据现场飞机和工程师阻止重复派机。不会删除旧档里已经生成的飞机或工程师，也未修改玩家存档。
- 保留现有美国伞兵共用的飞行、伞降和落点逻辑，未改遭遇战空投；以整支己方工程师和有效在途载荷判断损失，未逐条模拟零售触发标签、播报和引擎计时单位。

## 验证

Godot 4.7.2 无头，隔离 `APPDATA`，`res://tests/time_shift.tscn` 从苏军战役菜单出击。`--engineer-drop` 33 项（清理测试中登陆队原有三人；推进任务计时；用实际飞行和降落函数逐步执行首批投放；确认十人落地、剩一人不补、全失后按时只派一架载六人、飞机损毁后可补）。`--cold-engineer-drop --pending` 与 `--cold-engineer-drop` 各 4 项，用独立进程冷读首批等待、飞机在途档，继续后不重复发机。主线 51、`--power-ownership` 28、`--power-loss` 25，共 145 项通过，所有进程退出码 0 且 stderr 为空。日志 `%TEMP%/IT-S01-engineers-908bea60187f449c8ec7dab044801084`。逐步驱动用例不等同于完整自然飞行；未有头或手工通关，未直接冷读用户旧档，未打包。此前完整物理等待验证超时，不能作为已通过证据。
