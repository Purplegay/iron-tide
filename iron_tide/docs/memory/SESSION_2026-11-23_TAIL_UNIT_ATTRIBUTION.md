# 最慢5%帧归因：先查移动与战斗
基线：已合入行索引和销毁特效池的兼容冻结版 .validation/death-pool-3x/b；仅诊断副本修改，不是当前整树的性能验收。存档2/3，3x，图形Release，30秒，5AI，保留玩家。四场审计均有外部游戏负载。
证据：.validation/tail-unit-attribution/{s2,s3,phase2,phase3}/engine-phases.json 与 log；probe 和 phases 分别为两套独立插桩源码；ref2/ref3 是未插桩的1x参考。不要把不同场的数直接相减。
算法：按engine-phases的process_frame将相邻事件的usec差归到前一事件，丢弃首尾不完整帧，按整帧时长降序取ceil(N*0.05)。用frame号关联TAIL_UNIT或TAIL_PHASE，全部尾部帧对齐。下表为尾部帧均值ms，非P95阈值。探针时间含调度延迟，非原生函数自耗。
第一套s2/s3各199个完整帧，尾部各10帧。整帧320.72/298.52，物理回调201.13/192.02，process回调64.20/52.43，单位physics含子调用177.26/175.30。物理步4.6/4.3；单位调用1714.9/1475.2。_process_combat 33.18/40.00、_refresh_target 31.59/31.29、_move_water_safe 8.40/9.49、_tick_skills 6.17/5.67。方法累计按帧，可能嵌套或含其它入口，不可相加。

单位回调按源代码顺序分为六个不相互重叠的区段（含内部调用且早退归到退出时所在区段）：入口到embarked 39.39/34.89；embarked到_drive_heading 10.66/16.92；_drive_heading到主_tick_skills 4.74/5.48；主_tick_skills到logistics.tick分支 37.11/39.02；logistics.tick分支到Turn on arrival 49.82/56.95；Turn on arrival至函数结束17.55/18.94。
结论：按层级，物理回调 > 单位physics > 后勤、移动与战斗区段。该区段约占整个慢帧16.6%/19.2%，不是全部物理时间。先前爆炸占比2.2%/5.1%来自其它场次，不能直接扣减。
