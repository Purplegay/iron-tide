## 优先核对的玩家流程

1. 失败条件。原图 `_Lose` 为事件 11（DestroyedAll），现版 battle.gd::_check_end 在失去建造场且没有基地车时直接判负。应测试剩一辆坦克、只剩兵营和全灭三种局面。
2. 回收厂和村民。原图西南五路、东北四路生成居民或牛；九个出生点的房屋各自被毁后应停止相应路线。拆厂或占厂还牵动停队、两翼调查队、居民反应。现版 field_events、grinder_lost 只覆盖发现、换主/摧毁及部分增援。
3. 防守和后勤。三方开局 Bunker Boys 指定驻军目标，坦克有进坦克碉堡的行动，五组 Bio Loaders 有进入生物反应炉的行动。现版放置和区域警戒不等于执行这些进驻任务。城堡受袭会叫来工程师，但 castle_guards 的生成没有指派修城堡。
4. 敌军按战况出兵。原图 AITriggerTypes 有 74 条，含对装甲、科技和难度条件、权重与对应 TeamTypes。现版 attackers、combine 和 waves.json 五波脚本都存在，未找到第七关根据这张原表选择各房队伍的运行入口。
5. 超武反制。触发、语音和四座设施的放置已接。三条 Has ConYard 失去相应建造场时停用后续建造触发器；media_events 的定时生成只查解放标记。建筑通用发射与遭遇战 AI 选目标已存在，第七关自动实发路径未在本次查实。
6. 环境和收尾。东西墓室毁坏与对应灯组联动、Hello 格子事件、获胜后的分步解放/欢呼和延迟结算仍有差异。当前灯为创建时固定的精灵，城堡死亡即结算。
7. 混编车组已能招募、工厂增产、登车换炮和出击。原版十条 Combine ... KIA 死亡分支不宜仅凭自动补员判定等价；需分别在会合前、登车后、出发后打断队伍验证。
