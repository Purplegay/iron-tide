# 《脑死》验收经验总结

本轮按用户要求停止追查剩余 AI，只整理经验，不开窗口、不再跑测试，不改代码或存档。此前也已明确跳过自然通关和有头实景；这些项目未验，不列为失败或通过。以下流程可复用于其它尤复战役。

## 1. 把结论分成数据、流程和行为三层

- **数据对齐**：先锁定零售地图哈希和版本；任务与地图 AI 分表，分别核对 ID、原条件、启停、难度、动作、房号及编组。全局 AIMD 启用覆盖、任务增援、地图 AI 不混算。原版关闭项与空动作可以完整导入，但不擅自启用。`ALL07SMD` 正式数据为任务 88/88（含 4 关闭、1 空动作）、本图 AI 84/84；这是接入与数据核对，不是逐 ID 实战通过。
- **可玩流程**：从真实战役菜单进正式战场，覆盖出击、控制交还、关键门槛、胜利、普通失败、专属失败、结算与返回。明确哪些是玩家命令，哪些是夹具加速、摆位、注入伤害。既有无头门槛 20 组、751/751；补充断点和单队样本另有 10 组、265/265。断言数有重复覆盖，不相加成零售覆盖率。
- **行为对齐**：按脚本用途验结果。进攻看行军和伤害，驻防看全员到岗及入侵响应，工程师看实际到门转属。模型载入不等于画面正确，选队接令不等于抵达，夹具结算不等于自然通关。

## 2. 推荐的无头验收顺序

1. 用生产场景、真实菜单及 HUD 先跑一条主线和两条失败。隐藏窗口、隔离用户目录；性能或加速批跑关闭测试场景的自动存档，非远征不触发远征检查点。保留退出码、终止标志、覆盖行数和独立 stderr；只看退出码或断言不够。其它关并行改动引入的编译错误也要单列，不能宣布干净通过。
2. 存读档成对运行 `seed/cold`：在有意义的中间状态真实写档，退出后用独立进程读取，继续推进到玩家可见结果。至少检查不漏、不重、操控是否恢复、队列引用和资金是否一致。此次抓住三类好断点：前片回调已结束而后片未挂载、空投人员仍在半空、已出厂一人且下一人在产。别只在两段稳定阶段前后存档。
3. CG 把战场播放与收藏回看拆开验。收藏走真实页面，验证锁定雪花、已收藏同 ID 节选、双向拖动和返回。雷达片续音段的有效时钟是续音，不是已经播完的视频位置；用错时钟会误报拖动坏了。无头可以验证留帧对象、字幕文本与画音位置，不能替代实景观感和实际听读。
4. AI 先做短样本，再做逐 ID 矩阵。保持真实工厂目录、科技、队列、出厂和扣款入口，只隔离竞争候选，不注入订单。适用规则先测阈值差一，再测刚好满足；阈值为零单列。分列房号、适用难度、选队、实际消费、编制、接令和后续行动。生产可分段快进；移动与交火固定 `1/60` 秒步长，扩大步数而非膨胀单步。开场实际设施与人工补齐设施的结果必须分列。

## 3. 这次实测里最值得复用的经验

| 容易误判的地方 | 已确认的处理方式 |
|---|---|
| 把“运行 84 条”说成“84 条都能正常出兵” | 开场设施夹具只完成 68/84；另外 16 条在第三房设施/科技就绪夹具里完成。合并 84/84 只说明条件就绪后的生产链，不证明正常局会建齐。 |
| 所有队伍都要求打同一近场目标 | 先读 ScriptType、航点和攻击类别，再沿真实路线放匹配目标。超时保留当前命令、队列、剩余距离和目标可见性；走向别处不是卡住。17.5→60 游戏秒只新增 13 条伤害证据，不值得再统加时。 |
| 只给一队守军一个落脚点 | 这会把编队拥堵误当成无法驻防。按原航点分配可达且相互分离的落脚点；验全员到岗，再放入侵目标验伤害或心控。`11,11` 开场驻防与第三房先执行 `54` 再驻防不能合并验。 |
| 测试里只有某个队交火，但其他预置守军也开了火 | 只推进实际出厂队伍，隔离无人参与的伤害；可人为揭雾或摆靶，但要注明，这不证明自然侦察和跨图行军。 |
| 读档成功或 88/84 数据接齐就签发整关 | 坚持区分数据、无头流程、原版行为与发行。日志空不代表逐条证据齐全；缺证据写“未验”，不写“失败”或“通过”。 |
