# 存档 1 的 16 ms 结构方案

## 第一步：按推进一个物理步的成本复核桥面 A

两场已有图形诊断各推进 450 步。每步平均 386.43 / 392.28 次单位回调，共 35.352 / 35.544 ms。两场各自最慢的 5% 图形帧平均推进 5.429 / 4.875 步，单位入口 201.139 / 206.156 ms，AI 建筑选址 45.374 / 37.804 ms（含于阵营 AI）。整帧超时后同一帧承担多步，放大逐步工作。逐帧扣去单位计时再算 P95，在原采样时间线上仍有 168.600 / 154.979 ms；实际提速会改变补步数，这个算术不能预测候选成绩。建筑生产队列约 0.512–0.598 ms/慢帧，撤下主攻优先级。

## 第二步：验证让静止单位休眠能覆盖多少时间

另从冻结 A 做隔离插桩，存档 1、3×、固定工作量、900 个帧间隔，主游戏运行中。第一次参数不兼容，改用 fixed-workload 后取得有效样本。以下用同一次运行的单位入口计时作分母。按回调入口分类，类别互斥。

| 入口状态 | 次数 | 单位总耗时占比 |
| --- | ---: | ---: |
| 空军、采集、维修、载员等特殊状态（含死亡等早退） | 68,648 | 38.5% |
| 常规单位，无当前目标，有移动、命令或速度 | 63,008 | 37.0% |
| 常规单位，有当前目标 | 19,624 | 17.7% |
| 其余静止常规单位 | 21,068 | 6.8% |

静止组有 21,008 次到返回时仍在原地且无目标、命令或速度。它们仍可能处理冷却、恢复和避让。即便省掉这组全部入口工作，也只覆盖该次单位计时的 6.8%。移动与特殊状态的合计包括各自的独有逻辑，不能当作可共享工作量。插桩与无头负载会影响绝对值，此次未生成正式 A/B 成绩。

## 第三步：把可消除的重算写成一个可否决的 B 方案

首选试点是陆上 AI 建筑选址。一家 AI 已有准入预算，但一次搜索最多检查 72 个径向位置和 32 个补扫位置。旧 B 缓存候选点，在 32 对专项把完整判定从 1,136 次降到 536 次，正式整帧仍未通过。活动 A 已有补扫位置缓存。

新 B 让地图替各家保存“该建筑地基放在该格，已知会碰到哪个固定障碍”。只登记原判定能证明必然失败的理由，如与已有建筑地基实际相交；按地基形状、朝向等原判定输入区分。用反向索引把每个阻挡物关联到受影响的格和地基。当建筑创建、出售、摧毁或形状变化时更新依赖，重叠遮挡要能独立撤销，读档从当前世界重建。先只覆盖陆上、对固定建筑的精确拒绝；动态单位、视野、道路出口等继续用原逻辑。仍按原顺序找第一个合法点，保持补扫游标。预算先限制索引预热/维护，未完成的格走原判定，避免把一次建造决定推迟到下一步。

先在同一批真实请求中旁路计数，统计“同一地基和点因同一未变的建筑再次失败”的次数与原判定用时。若可省时间很小就停止此试点。出现实质覆盖才接入跳过逻辑。固定输入逐步核对选点、失败、游标、建造时刻；记录内存、初始化、成片拆建后的重建和最慢帧。新热点如果转到动态占用或出口，按实测记录。正式合入仍按存档 1、桥面 A 原成绩、空档两场 3× 再两场 1× 的既有口径。

单位另有更大的结构性成本。后续先在无目标的移动组，将同一移动命令中多个单位读取的目的地、通行类型及静态地形路线按依赖版本共享；保留各自编队落点、即时避让、接触、碰撞和命令切换。先核对已有路径缓存的覆盖和实际共享输入，再估算能消除的耗时。若每步成本仍高于 16 ms，需拆分可提前计算的只读任务、限制每个呈现帧的工作量，并核对模拟进度、输入延迟与可见状态；单纯减少补步上限会把卡顿转成模拟欠账。

本轮仅诊断和设计。正式 A 仍为桥面版，存档 1 两场 3× P95 为 300.596 / 235.400 ms。复核脚本与原始分类见项目下 `.validation/slot1-architecture-20261124/budget.json` 和 `timedA2/summary.json`（后者位于同目录）。
