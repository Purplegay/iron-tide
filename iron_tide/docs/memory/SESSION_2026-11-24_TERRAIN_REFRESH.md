# 建筑摧毁后的局部路线失效

## 操作记录

以下按实际操作补记。各档的完整数值见后文。

1. **锁定 A。** 从上次合入的建筑视野覆盖格版本取三个存档各自的完整源码和输入，核对存档、meta 和引擎指纹，沿用留存的 3× P95。[上一成功版本的三档清单](../../.validation/three-save-path-20261123/active-baseline.json)
2. **追踪重规划来源。** 在 A 的地形重建入口记录调用方，再与单位找不到变更范围的版本号对应。三个存档分别有 98、176、235 次指向建筑摧毁后的延迟重建，因此先处理这个入口。[档 1](../../.validation/terrain-refresh-20261124/diaga1/timers.json) · [档 2](../../.validation/terrain-refresh-20261124/diaga2/timers.json) · [档 3](../../.validation/terrain-refresh-20261124/diaga3/timers.json)
3. **制作 B 并修正快照。** 合并同批摧毁建筑的占地，核对范围外网格和障碍。第一版直接保存数组引用，最小实验确认原地写入会同时改变旧值，随即改用五份独立副本。早期候选计时从合入依据中排除。[共享数组复现](../../.validation/terrain-refresh-20261124/ownership/check.gd) · [修正操作](../../.validation/terrain-refresh-20261124/correct.py)
4. **用同一输入复测。** 固定 64 个单位和两座建筑，用 A、B、B、A 四个独立进程回放，把新增的建筑刷新开销也计入。两组中每批重规划都从 64 次减为 8 次。[回放输入](../../.validation/terrain-refresh-20261124/fixture.gd) · [分项计时](../../.validation/terrain-refresh-20261124/local.json)
5. **检查行为边界。** 覆盖范围外网格或形状改变、两座建筑同时摧毁、相交路线和部分路线，并跑导航、桥段、海军和 AI 受阻专项。隔离候选通过 540 项断言，其中一项逐格核对 500 种变化。[回归结果](../../.validation/terrain-refresh-20261124/qa.json)
6. **分别测整帧与函数。** 三档各跑两次 3× 图形实战，三个存档的最好 P95 和两次均值都变慢。另用固定 450 个物理步测重规划、转向父函数和建筑刷新，逐档保留调用数及毫秒数。[整帧原始数据](../../.validation/terrain-refresh-20261124/three.json) · [固定负载计时](../../.validation/terrain-refresh-20261124/local.json)
7. **处理并发干扰并补测 1×。** 存档 3 的函数计时遇到其他游戏进程，保留并发样本，待进程退出后用同一输入补测。存档 1 缺少旧版 1× 参照，从冻结的 A 补齐两场。最终表采用通过进程审计的样本。[存档 3 替代记录](../../.validation/terrain-refresh-20261124/fixed-review.json) · [最终 1× 对照](../../.validation/terrain-refresh-20261124/one.json)
8. **合入并复验。** 用受控回放和无干扰实战确认局部收益，合入开发树，再次通过 540 项断言。最终三档校正后的转向加建筑刷新累计从 1,632.9 降到 1,483.4 ms；存档 3 单档转向变慢，三档整帧回退也一并保留。[合入决定](../../.validation/terrain-refresh-20261124/decision.json) · [开发树复验](../../.validation/terrain-refresh-20261124/live.json)
9. **固定新 A，交接下一热点。** 保存完整源码、三档函数耗时、3× P95 和 1× FPS。下一轮拆分单位目标刷新 `_refresh_target()` 中的已有目标复核与新目标扫描。[新 A 清单](../../.validation/terrain-refresh-20261124/active-baseline.json)

本轮根据用户更新的判法，直接检查目标函数或其父函数的耗时，另算转移到其他函数的工作。三档图形整帧 P95 与 1× 平均 FPS 仍用于跟踪整体体验。每档候选均叠加于上次成功版本的完整源码。存档 1 使用 v0.31.20 及冻结玩家存档，存档 2、3 沿用 v0.31.16 兼容快照。同一档的正式对照沿用上次成功版本的留存值。

在原版三档各一次的首轮 3× 原因探针中，建筑摧毁后的延迟重建导致 98 / 176 / 235 次完整路线因缺少变化范围而重算。断桥更新及存档恢复仍保留全图失效。只用早期探针辨认来源。独立数组副本修正前的候选采样排除在正式计时和合入判断之外。

候选在同一批建筑摧毁时合并占地。同步重建前保存五张通行网格的独立副本及范围外的实际障碍形状，重建后检查范围外的每段网格及障碍形状。全部一致时，将该范围记入已有的路线版本历史。完整远端路线可以继续使用，穿过变化范围、部分路线和缺少记录的路线沿用原有重试机制。该地图为 163×163 格，五张 float32 网格的原始数据合计 531,380 字节，暂存于一次同步重建内，另有形状引用与比较切片。
