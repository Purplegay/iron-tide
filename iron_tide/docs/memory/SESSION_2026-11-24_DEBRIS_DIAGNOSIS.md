# 残骸变多时的卡顿排查

1. 源码核对。YR 车辆、飞机和部分建筑的抛射碎片共用 `yr_vehicle_debris.gd`，按 1/60 模拟秒子步遍历，落地可触发伤害和特效。伤害分发复制并遍历战场单位与建筑，预算 64 位于每次 drain。RA3 模型残骸则使用独立 3D 视口。永久建筑废墟有单独的重建路径。
2. 三档自然战斗取样。v0.31.30 开发版无法直接进入旧存档 2；保留退出记录，改用三档各自的已接受源码快照，五份相关残骸/爆炸脚本均与开发版逐字节相同。隔离运行时以逐帧计数器记活跃碎片、生成、子步、落地伤害扫描、绘制和特效，并保留正运行的游戏。各计时可能嵌套，不能直接相加。采样写入 `.validation/debris-diagnosis-20261124/`。
3. 控制试验。自然采样结束后，在同一战场选远离单位和建筑的陆地点，分别同时投入 1、8、24 片原生 PIECE，将落点及速度固定，重复交替打开和关闭碎片伤害。比较真实释放和着地调用；不将试验写回玩家存档。RA3 单独在私有图形桌面对同一批模型交替启停视口更新，保留姿态计算。

控制组保留原生 PIECE 的落地特效，每组交替测试，有无伤害各取三次的中位数。存档 2 自然战斗一帧 377.149 ms，分发了 62 次碎片相关范围伤害，逐次按当时的单位和建筑数共计 36,394 个候选，碎片推进含子调用 88.191 ms，绘制回调 3.360 ms；同帧所有来源的爆炸还有与碎片推进重叠的耗时。慢帧还受其他工作影响，存档 2 最慢 17 帧里只有 6 帧测到碎片范围伤害。
4. 单独重复存档 2，在落地处理中分别包围桥段检查与完整目标循环。24 片有伤害时 28.851 ms 的中位测试内，27.902 ms 位于单位/建筑目标循环（96.7%），桥段检查 0.119 ms；同场无伤害中位 0.385 ms。落点远离战斗单位，命中很少也要遍历全场；子步、烟迹与绘制有额外成本，此项验证最直接。
5. RA3 专测用开发版 R3FUTURE，RTX 5060 Ti，1600×900，私有桌面，保留模型运动计算，重复切换视口更新。6 具同屏时整帧 P95 1.139 → 2.302 ms，绘制调用中位数 6 → 66；首具构建 143.291 ms，随后 7 具 26.116–51.427 ms。同型号后续复用网格，创建仍有成本。这组独立场景没有完整战斗负载。三档自然采样均未观察到 RA3 模型残骸或持久建筑废墟。建筑的 leave→restore 会遍历并重建同场所有废墟，此轮只做源码确认。
