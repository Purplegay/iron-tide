## 正式结果

正序、反序 3× P95 分别为 220.668 → 210.536，179.181 → 165.012 ms。最好 179.181 → 165.012 ms，两场均值 199.925 → 187.774 ms。1× 平均 FPS 19.292 → 18.563。候选未合入，当前 A 继续使用陆海共享敌情版。 测量期无其它游戏引擎，各场其它 CPU 估算 A/B（%）[(24.1, 20.3), (18.1, 17.9), (21.9, 26.1), (17.6, 15.3)]。所有正式 B 测量的源码清单一致，冻结 A 与开发树作用域已核对。原始报告位于 .validation/slot1-shot-work-20261124。

### 慢帧变化、归因与下一步

慢帧中 A/B 每帧平均推进 3.09 / 4.20 个物理步、发射 9.64 / 13.10 次。发射含子项由 1.047 降到 0.851 ms/发，但调用更多，导致 10.091 → 11.151 ms/慢帧。整帧还受其它区段与主机负载影响，不能由这组插桩量完全解释。单位绘制 10.970 → 19.585 ms/慢帧；每慢帧平均 378.3 → 503.6 次，每次 28.999 → 38.890 μs，两项均上升。下一轮先在活动 A 拆 unit._draw_pose() 的车体、炮塔和附加特效，按同兵种、朝向、动画帧及实际绘制次数对齐，再决定哪些绘制数据可缓存。

整帧 P99 补充（正序、反序，各为 A/B，ms）：[[285.413, 244.145], [211.055, 192.811]]。开发工程 v0.31.31，固定图形计时链 v0.31.20。本轮开发树目标文件与制作候选前的字节相同。
决定维持 A 的直接原因是 1× 两场 FPS 均低于各自 A。1× 正序后台 CPU 约 21.92% → 26.07%，反序约 17.64% → 15.35%，方向相反。3× 插桩不能解释 1× 整帧退步，具体原因尚未定位。
