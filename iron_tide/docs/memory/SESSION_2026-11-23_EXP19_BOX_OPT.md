# 第 19 关框选优化

生产改动在 `scripts/ui/hud.gd`。按本局出现的友军兵种收集头像路径，去重后每个显示帧最多预读一张，HUD 持有资源到战斗结束。框选切到部队面板时跳过已收起生产栏的同步刷新，展开时刷新目录。生产队列事件、定期刷新与选中成员计算沿用原逻辑。

沿用 `.validation/exp19-20261123-1706/` 主档和窗口回放。1 倍速，每次启动均从相同检查点开始。证据为 opt-A1/B1/B2/A2.log，A 是这次改动前的 HUD，B 是改动后版本。四次均框中 66 个单位。首次框选的同步耗时依次 37.944、17.012、27.595、21.869 ms，松手首帧依次 109.804、74.119、83.621、80.445 ms。清空再次框选的首帧依次 80.916、47.899、65.287、53.604 ms。首次首帧均值 95.1→78.9 ms，重复首帧均值 67.3→56.6 ms。每版仅两个进程样本，区间重叠，结果用于说明本次存档观察到的差异。固定模拟时钟的开发引擎回放，尚无 Release 的多场景性能验收。

selection_regression 在两版独立用户目录验证流程中均 208 项通过 200，失败项完全相同。每种规则各四项混编时单独头像右键取消的旧断言，与当前混编按兵种分组的展示冲突。结果见 selection-check、selection-check-old。玩家主档只用于最初的复制。
