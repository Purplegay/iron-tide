# 车辆穿越建筑间隙的候选筛选

**本轮未合入。** 目前最近一次成功版本是移动流场扩展，开发版本 v0.31.20。用于冻结存档的兼容源码版本号为 v0.31.16。本轮候选直接复制上次成功版本的完整冻结源码，在其上只改 vehicle_passages.gd。八场候选各有 1,320 个源码清单项。逐场核对后，原有流场文件哈希与上次成功版本及当前开发树一致。[成功版本交接](SESSION_2026-11-23_ROUTE_STEERING_FLOW.md)

## 候选与测量

改动集中在间隙编号的筛选。候选将横向和纵向间隙的排序坐标分别存入连续数组，用二分查找确定区间，按两个区间复用已排序的编号。缓存计费上限为 8,192 项，每个区间占一项，每个保存的编号另计一项。添加间隙后在下一次查询重建，场景重置时清空。宽度、行驶方向、半径、路径长、静态轮廓和在场单位的检查仍使用上次成功版本的代码。

在最近成功版本的独立分段采样中，存档 2 最慢 5% 的 12 帧、存档 3 的 11 帧均有相邻的完整采样边界。候选间隙筛选平均占每慢帧 1.565 / 2.079 ms，净空判断里的建筑分桶准备占 0.479 / 1.343 ms，扫建筑与轮廓占 0.324 / 0.802 ms。探针以相邻渲染帧首次路径请求为边界，数值用于热点归因。[完整分段与计数](../../.validation/passage-clearance-fixed-3x/profile.json)

## 行为验证

- 存档 2 的隔离 3× 实战对照了 2,243 次完整路径和 1,851 次候选编号列表，路径、候选及顺序均零差异。观察到缓存最多 8,133 个计费项，排序坐标最多 462 个。
- 存档 3 的隔离 3× 实战对照了 2,692 次完整路径和 2,189 次候选编号列表，路径、候选及顺序均零差异。观察到缓存最多 8,190 个计费项，排序坐标最多 458 个。

使用当前开发树源码的隔离候选，通过 19,020 项定向检查，包含重置、追加几何、边界相等、32 个间隙的索引切换、缓存容量、编号顺序和结果数组独立性。另通过间隙索引 65,732 项、矿区 171 项和地基通行 17 项断言。坦克与步兵通行专项通过 36/40 项。RA2 及 IronTide 两种模式的门内闲置步兵侧移、侧移避开地基各失败一次。在未应用候选的当前开发树副本中复现了相同四项失败。间隙索引复用既有完整行为断言，省略其历史计时段。[隔离回归](../../.validation/passage-clearance-fixed-3x/candidate-qa/qa.json) · [实战路径及候选编号对照](../../.validation/passage-clearance-fixed-3x/paired.json)

## 下一热点

下轮从同一成功版本出发，测净空查询为短路线收集建筑的成本。两档所有通过地形筛选的查询分别提供 93,827 / 199,312 个建筑候选，真正访问了 32,413 / 63,035 个，包含已有全表和空间分桶两种分支。先单独量分桶分支在首个障碍物前访问多少，再试将分桶去重与阻挡检测合并，遇到首个阻挡立即返回。
