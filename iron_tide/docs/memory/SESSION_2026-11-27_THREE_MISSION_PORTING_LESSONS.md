# 三关战役收尾经验：怎样判定规则会启动、动作有目标、读档能续接

三关的最后八条任务里，一条影响六座原版电厂，七条都有原标签却没有绑定对象。两种结果都可以从 MAP 里复查。苏一另有 120 条继承 AI 缺少自然启动证据，这次按已确认的范围停止补接。任务最终有接线 674／681 条（含 656 条部分接线），另有 7 条按原图无绑定结项。AI 仍为 154／275 条进入评估或调度。[任务台账](THREE_MISSION_TRIGGER_COVERAGE.tsv) · [AI 台账](THREE_MISSION_AI_COVERAGE.tsv)

## 苏一的 AI 开关还要查哪一层

苏一 MAP 的 `[AITriggerTypesEnable]` 有 165 条逐 ID 启用设置。地图的 302 个 `[Actions]` 条目共 1236 个动作，其中启动生产（3）、自动编队（13）、启动 AI 条件（74）均为零。检查另一种指令源时，沿地图 TeamType 的 Script 字段和继承规则的主、副队伍追查，并扫描两份来源的注册脚本。苏一地图有 130 个 TeamType、102 个注册 ScriptType，共 357 条脚本指令。AIMD 有 88 个注册 ScriptType，共 458 条指令。这两份脚本都没有队伍脚本指令 29（启动生产）。队伍脚本与地图动作各自解释编号，脚本经变量间接触发的后继也要回到 MAP 检查。

原版房屋逻辑区分生产、自动编队和 AI 条件评估。即使房屋 IQ 满足生产门槛，全局选队仍另查条件开关。此前在隔离夹具中给 Americans 配齐设施和资金，手动进入正式选队入口，两只警犬能按原编制先后出厂。这证明了获准选队后的生产和续训。对这 120 条能落笔的结论是“在已查地图、脚本和房屋路径中，未找到自然启动依据”。没有原版自然游玩的完整轨迹，永久不可达仍无从断定。[第 25 批房屋逻辑与警犬试验](SESSION_2026-11-27_THREE_AI_BATCH25.md)

## 同为动作 14，为什么一条影响六座，七条没有目标

`0C46AB3C` 是《时空转移》返城时的转属动作。从末端向前沿 Triggers 的链接字段查，得到 `097DDE6C → 0951918C → 0C46AB3C`。标签 `0C46AA5C` 指向链头，再查 Structures 的标签字段，正好命中 GAPOWRA 至 GAPOWRF 六座原厂。时机由另一条关系决定：`0BDC985C` 启用 `0BDCDD0C`，后者等待 8 秒启用末端触发器，再过 1 秒把仍存在的目标转交 Americans。2.8 秒旋涡已经消耗这段计时的一部分。

对照的七条同样执行需要绑定对象的动作 14。逐 ID 反查所有链接前驱和标签，扫描标签定义外所有 MAP 段，结果如下。原图既有起始启用的条目，也有被其它动作启用或强制的条目；这些执行来源本身没有提供转属对象。

## 六座电厂怎样验证换时代和冷读

第一次穿越前，用原厂类型、原标签和地基中心定位各厂，记录当时存活原厂的归属、生命及维修、俘获状态。侏罗纪只保存记录，返城再恢复实体。测试场放一座玩家另建的同型厂作对照，转属前后都检查它的归属。

| 独立进程冷读的位置 | 测试安排 | 能区分的错误 |
|---|---|---|
| 侏罗纪，原厂暂时离场 | 穿越前在供电阶段击毁 F 厂；冷读时应有五份存活记录 | 从地图模板重建六座会复活 F 厂 |
| 返城，转属尚未发生 | 五座恢复后，在动作执行前摧毁 E 厂；到点只转四座 | 缓存旧目标清单会操作已毁建筑，重新起算计时会延迟转属 |
| 转属已经发生 | 冷读后重新占领一座并推进时钟，玩家仍持有该厂 | 重发一次性转属会夺走玩家刚占领的厂 |

首次损毁测试选在开场保护期，攻击没有击毁 F 厂。把操作移至可受伤的供电阶段，先断言 F 厂确已死亡，再种档和冷读。这样才能把“夹具没有造成损毁”和“换场复活了电厂”区分开。第 26 批最终八组隔离无头回归共通过 198 项断言；本总结沿用该批运行记录。[回归场景与逐组结果](SESSION_2026-11-27_THREE_TRIGGER_BATCH26.md)
