
# 存档 1 攻击模式与移动射击

1. 冻结图集预热 A 及已有成绩，存档 1、成长配置和引擎哈希已核对。标准留存场保持玩家席位，但没有人工进攻操作；另建私有桌面操作专项。源码区分 A 键攻击、X 键攻击移动（遇敌停下开火）与普通移动时转炮塔射击。

2. A 攻击键切换 1.075 ms，模式中光标单样本 4.131 ms；普通选中 2.588 ms。普通移动交火 16 帧，P95 517.782 ms，测试小队 11 发，包括移动中 1 发。攻击移动阶段小队 0 发，这段不能证明交战性能。3. B 复用同一次采样的像素命中结果，X/移动指针提前返回；点击仍重新采样。另试普通枪无目标无连发时跳过开火入口，独立炮架仍由原入口推进。测试先覆盖武器缺目标、连发取消和时间推进，正式成绩仍用冻结 A。

4. 复核发现存档 1 的 enemy 席位与玩家可能同队，首轮插桩记录到的射击不能都归于预设目标。专项改为从存档外交关系选实际敌对席位，给双方测试坦克留足生命，并固定相同点位、模式、次数另测光标。原采样作探索留存。

5. 原攻击光标 72 项、武器逻辑 2706 项、炮架 432 项通过。强制攻击 200 项通过，第 201 项跨进程读档受 release 引擎不支持 --path 影响；专项脚手改为在同一隔离 cwd 由子进程加载同一用例，保留所有断言。额外移动演练首次因测试父节点禁用导致物理体不在空间，已将两辆测试车接回物理空间，保留旧日志。原版 rules.ini 在 OpportunityFire 中将移动中交火与移动指令区分，GuardRange 描述单列索敌距离。

固定演练两版 3× 各模式 90 个物理步；逐步射击数、冷却、连发余量一致。普通移动 357 像素，4 发（移动中 1 发）；攻击移动对射程内目标停下，5 发；直接攻击 5 发。
