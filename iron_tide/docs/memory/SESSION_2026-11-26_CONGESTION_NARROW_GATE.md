# 常态移动下钻：拥堵检测不用转向宽名单（2026-11-26）

接 [移动与碰撞复测](SESSION_2026-11-26_CURRENT_MOVEMENT_P95.md)。用户明确要求沿热点逐层下钻，每层核对输入、输出、淘汰原因；如果下层收到太多候选，优先找上层筛选问题，不只在末端微调。此要求作为后续性能工程原则，记入 `PERFORMANCE.md`。本轮隔离候选、未改正式代码、玩家存档、桥梁规则，未提交打包。

## 逐层核对与最窄候选

- `Unit._physics_process → tick_congestion`：无资格单位仍走旧保护；已经穿行的恢复碰撞分支保留，既有滑动撞友军也优先原样判定。问题只在没有实际滑动碰撞、要判断前方有无近身阻挡的分支。
- `tick_congestion → ensure_candidates → _can_reuse_candidates / _rebuild_candidates`：旧分支为了得到一个布尔值，维护 `自身半径 + 60 + max(60, 速度×0.8) + 64` 的转向/避让宽名单。成本含锚点、版本格、同格 Watch 校验，失效则按桶取候选并分生成名单及 Watch。
- 候选隔离代码 `candidate-source/scripts/units/local_traffic.gd::_congestion_blocker_ahead` 只对 96+ 单位且本地/全局坐标一致的非步兵采用 `自身半径 + 最大单位半径 + 8px` 的即时查询。保留原前向点积、严格距离、碰撞层、友军、穿行判定；只取布尔值，不改变对象、不把候选重排给避让、不触碰桥层。小场景、步兵、坐标不一致继续旧入口。移除拥堵分支宽名单预热意味着 `apply/open_corridor/stalled_blockers` 仍会各自执行原校验；不假设预热成本全部消失，也没有用物理帧号缓存。该候选与旧的 256px 扫掠框 + `wide.find` 判退不同，不做二次交集或排序。
- 影子不改原执行：旧查询 77,805 个名单项、实际遍历 75,871；窄查询 35,287 个边界桶格，返回 100,101 项、实际遍历 97,852。窄半径落在粗桶上，**桶内迭代反增 29.0%**；原形状命中均 2,846，且各自进一步查出 608 次挡路。这不是“对下层少传了桶成员”，而是更早绕过一整套不需要的宽名单维护。下一候选应区分“缩小几何域”和“减少真实桶成员”这两件事。
