# IronTide 性能优化流程纠正（用户明确要求记忆）

- 用户要求后续性能优化先对当前版本、代表性的六家对局完整打点，找出真实耗时 Top 10，再按热点顺序优化。不要沿用旧热点、只做零散的小缓存或人为缩小优化范围。
- 报告函数的自耗时、含子调用总耗时、调用次数及自耗时占游戏脚本自耗时的比例；同时查看自耗时与含子调用耗时排名，避免把父子调用重复相加。区分游戏逻辑、测试脚手和计时开销。
- 以新测量定位根因，参考 Yuri 的结构时核实实际源码证据；每次改动后重新测量热点，并用相同场景、输入和运行条件的 Release headless 完整帧 P95 配对验证。局部函数提速或 Debug profiler 数据不能代替整帧收益，未通过的候选不合入。
- 保留 AI 公平性和游戏正确性，不靠降低模拟工作量来冒充优化。当前阶段目标为六家场景完整帧 P95 <= 90 ms；headless CPU 验证不等于显示帧率或 GPU/实机表现验收。

来源：2026-11-16 用户纠正“不是让你打点做用时最多的函数去做优化top10吗”，随后明确要求“这个方法记得写入记忆”。
