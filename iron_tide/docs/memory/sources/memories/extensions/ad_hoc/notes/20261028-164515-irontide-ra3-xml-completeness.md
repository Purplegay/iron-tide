# IronTide RA3 复刻：逐项 XML 分析与补缺要求

用户于 2026-10-28 明确要求：“我们复刻ra3的东西你得逐个分析xml干了什么，缺了的就补，这个要写入记忆需求”。这是对既有“RA3 改动参考官方 SDK”规则的加强，适用于 C:/Users/admin/IronTide 中所有后续 RA3 / 起义移植、补充与修复。

- 以单位或系统为范围，逐项解释官方 XML 实际执行什么；追踪 Includes、inheritFrom、覆盖/替换、默认值和引用链，不能只读取主单位文件或复制几个数值。
- 对照 Draw/ModelCondition/AnimationState/Transition/Script、骨骼和炮口、移动与转向、武器与弹匣/预攻击、技能准备/持续/收起/冷却、粒子与材质、声音、生产、死亡残骸、晋升及英雄变体等实际相关配置。
- 每项建立“源文件/对象或字段 → 原版作用与触发条件 → 当前代码/资源 → 验证证据 → 缺口”的可追踪对应，区分仅导入素材、实际接通运行调用、逻辑通过和用户表现确认。
- 当前范围内能从官方源确认的遗漏应主动补齐，不等用户逐个报错；不能以部分能运行或模型已导入就声称整个单位复刻完成。仅 Include、被注释、空事件或未被状态调用的素材不凭名称擅自启用。
- 沿用官方 SDK 和合法本机起义资源作为来源，记录版本及单位换算；不混用尤复 15 帧时钟。无法从公开 XML/着色器/原始资源确认的 SAGE CPU 行为明确标注证据缺口与 Godot 适配，不能编造“原版相同”。缺资源继续追踪来源，无法补齐的逐项交接。
- 验证真实调用入口、状态转换、取消/死亡/读档等相关边界；画面和手感保留用户验收。已有明确用户定制规则继续有效，发现原版与定制冲突时说明差异，不直接覆盖。

本次仅记录长期要求，不代表已对所有 RA3 单位完成全量 XML 审计。项目交接入口：docs/RA3_PORTING.md。
