# 存档 1 的交战射程计算

`Unit._process_combat` 已写入开发工作区。目标域检查通过后，没有乘员射击路径的固定射程单位直接读取实时 `attack_range`，省去通用射程函数。驱逐舰保留反潜接触射程，双武器保留按目标选射程，无畏级保留建筑底盘修正。无畏级在当前兵种表没有独立防空武器，检查追击点时可复用本次交战得到的射程。开放载具或存在战役射程附加时，追击点沿用原射程查询。无畏级与驱逐舰的保留分支依据 `OpenTopped.command_range` 的底盘和原版 ASW `Range=-2` 接触语义。候选只改 `scripts/units/unit.gd`，无新增状态或调度间隔。

同一存档 1 的隔离夹具在 Godot 4.7.2 图形 Release 中运行，开局 381 单位、207 建筑、5 个电脑阵营，3 倍速，每场约 30 秒。四场通过源码、模拟推进和外部引擎进程审计。

同期两场 P95 均值 291.358 → 255.650 ms，最好值 275.554 → 245.310 ms。上一次正式留存的属性重算版为 289.585 / 273.356 ms。该版此前另有后台负载更低的场次，原基线曾测到 212.359 / 201.095 ms。此次候选两场的后台负载均低于同期基线，整帧差额不能单独归因于代码。按留存基线、同期测试和行为回归门槛保留。

独立分段探针在基线 134 帧中取最慢 7 帧，在候选 163 帧中取最慢 9 帧。交战入口的含子调用平均耗时 36.973 → 35.752 µs/次。全局 `command_range` 含子调用平均 7.153 → 4.711 µs/次，调用类型比例会随战场进行而改变。这些是带插桩的不同战斗样本。单步节省和整帧改善不能直接换算。
