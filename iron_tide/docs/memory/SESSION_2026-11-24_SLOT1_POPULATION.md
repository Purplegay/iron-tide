# 存档 1 的 AI 人口重算
沿用活动桥面 A 及冻结存档 1。用隔离图形探针分别计时单位、建筑生产队列的遍历，追踪死亡回调直接触发的查询，并将同帧可复用的死亡前计数与完整重算核对。

两场 A 计时后，在第三个存档 1 副本用独立字典真实计算延迟队列。每次需要预留人口时与原实现逐阵营对账，普通单位死亡保留同帧队列，跨帧、建筑死亡及其它显式失效照常重建。影子计数不参与游戏决策。

源码核对：生产入队、取消、成功出生、阵营转换、读档与淘汰触发人口缓存失效；生产完成先移除队列条目再尝试生成单位。运输车改阵营也会改乘员阵营，基地车展开会直接从单位表移除。构造 34 人阵营同帧连带死亡，检查半数补员阈值及死亡通知内的读数。

存活人数的直接读取者有动员、补员及开战 AI。普通生产容量和额外桥梁工程师的预留检查还读取排队数，后者直接访问 _queued_by_house。失效包括单位出生、死亡信号、厂内入队与取消、建筑出售、阵营转换、阵营淘汰与读档。支援飞行单位不计数，登车乘员仍计数；展开基地车直接移除单位。生产完成先出队再调用 spawn_unit，不能把所有队列变化都等同于成功出生。

**直接减一验证。** 前两场，死亡回调前仍有同帧有效计数的 35/22 次样本中，受害者所属阵营旧人数减一与完整重算分别有 1/4 次不一致。自然样本没有保存事件链，不能断定这 5 次均为运输车。同帧连带死亡专项在 34 人时击毁载有一名乘员的运输车，首次通知已剩 32 人并触发补员；使用旧 34 减一会得到 33。第二次通知到来时上次权威值已是 32，再减会得到 31。仅靠死亡回调扣减会错过阈值时序。

**真实队列影子对账。** 第三场原实现重建 425 次；独立字典仅在实际需要预留容量时枚举建筑，同帧普通单位死亡保留队列、建筑死亡及其它显式失效清理。实际重建 203 次，3178 次读取对照原实现为 0 次差异。该场外部引擎检出 True、后台 CPU 约 71.9%，只用于计数一致性。前两场的 lazy_builds 统计仅模拟调度，未作为独立对账证据。
