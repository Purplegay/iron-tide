# 2026-11-27：Ctrl＋右键攻击移动卡顿

用户报告攻击移动特别卡，未提供关卡、规模或发生时点。`Battle._issue_order` 在 Ctrl 分支直接交给 `_command_move(..., true)`，其编队分槽和寻路与普通地面移动共用。在隔离 70 辆盟军灰熊、90 辆敌车的真实战场场景夹具里，两种指令的同步提交约 3.7–6.4 ms，未见攻击移动独有的下令开销。攻击移动则放宽自动索敌距离：本例射程 275、视距 320，一批单位在射程内外同时接敌，原本还会继续解析大量注定无法胜出的候选。

## 实际改动和语义

- `scripts/units/unit.gd` 的 `_refresh_target`：仅攻击移动、已经取得本次同步查询共享武器、且已有分数严格高于射程外移动目标上界时，跳过射程外移动对象的后续武器、域/视野、墙体与评分检查。共享武器已建立，避免跳过会初始化共享武器与拒空标志的第一次解析；未改变空间索引、外层索敌频率、扫描顺序、平分处理、路径、射击时钟或存档字段。
- `scripts/core/tactical_targeting.gd` 抽出既有 16 分射程外扣分并放置保守上界。移动目标最多有 4 分效能、4 分齐射、0.6 分残血、0.5 分当前目标奖励，不吃建筑加分，距离只扣分；扣 16 前向上放宽到 10。严格大于才剪枝。建筑（含 C4）、DTRUCK 边缘距离、未建成共享武器的特殊路线仍原样处理。只有射程外目标时不会因这道门槛而丢失它。
