# 第 19 关远征框选耗时诊断

证据目录 `.validation/exp19-20261123-1706/` 包含 17:06 主档和备份、回放工程与原始日志。两档均为第 19 关战斗，主档 yr_mojosprt 恢复 209 单位、74 建筑。测试只在独立用户目录运行。首次暂停样本丢弃。

Godot 4.7.2 窗口 OpenGL，RTX 5060 Ti，1 倍，固定模拟帧率 60，用主档恢复完整场景。先等待 40 帧，以 600×360 矩形覆盖友军密集区，分别观测空选、模拟拖框重绘、调用真实 _apply_selection、清空并重新框选，各 80 帧。模拟拖框未注入连续鼠标运动事件。固定帧率只控制模拟时间，记录的是实际墙钟间隔。诊断数据不代表打包版玩家 FPS。

select.log 中两次选中 66 个单位。空选、拖框、保持选中、清空、再次选中的中位数依次为 23.458、20.879、25.964、20.398、25.118 ms。两次松手同步调用耗时 19.471/16.805 ms，首帧 80.355/57.028 ms。

select-hud.log 独立重放对 HUD 分项计时。两次同步调用 20.025/16.589 ms，其中 HUD 回调 17.340/14.023 ms。头像栏重建 7.676/5.781 ms，技能栏 3.268/2.375 ms，增益栏 1.239/0.985 ms，生产栏 2.446/2.631 ms。父子计时重叠。首帧 76.769/56.462 ms。分项能解释松手同步处理，剩余首帧和持续选中开销尚未完全归因。

前置无头对照 run-base/run-static.log，正常推进 P95 67.041 ms，禁用恢复时场上单位的物理回调后 14.421 ms，此消融改变战局，仅用于定位基础负载。生产代码和玩家原档均未修改。
