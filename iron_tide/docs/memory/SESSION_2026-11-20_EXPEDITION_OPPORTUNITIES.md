# 2026-11-20 肉鸽优化建议审阅

用户询问“肉鸽还有什么可以优化”。本轮只读审阅并提出建议，未修改玩法、数值、生产代码或玩家存档，未运行测试。

查阅 docs/memory/EXPEDITION.md、仓库上层 docs/EXPEDITION.md，以及 scripts/expedition 的 screen、market、run、reinforcement_plan。

已实现，避免重复建议：路线地图/对手/资金/目标/Boss预览；羁绊3/6/9和最多两个追踪；商店定向编制槽及锁定；奖励Buff当前等级与获得后等级；满级商品过滤。随机权重/定向已有基础，不能称为完全缺失。

优先候选（均未获实施授权）：
1. 奖励卡收益预览：具体受益兵种/人数、羁绊当前→选择后层数、是否触发3/6/9节点，供玩家比较选择。
2. 营地增援计划预览：复用reinforcement_plan.delay_for/build，列基础时间、英雄训练额外延迟、超时空减时、最终抵达时间；勾选出战后更新，不改每局重新排队规则。
3. 战后复盘：screen.build_history与run胜利history目前主要记录关卡/地图/补给/局外收益；补充用时、军团伤亡/待到达、英雄真实阵亡、自动出售与补给收支。若增加承伤/输出需另审计采集开销。
4. 后期营地信息密度：build_equipment顺序展开全部装备，军团每卡多段文字；可提供折叠、筛选、待处理优先。
5. 自然游玩经济和失败原因统计后再做数值平衡，关注首次英雄到场、补员/强化/商店取舍、章节损失；不凭现有脚本通关推断自然难度。
6. 后续玩法内容可考虑有明确预告的精英词缀及支线取舍，须先评估已有任务/事件，避免重复。
