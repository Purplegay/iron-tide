# 尤复战役迁移

以苏军第七关《首脑游戏》的**整关迁移方法**为范例，不复制那一关的数值、触发器或近似实现。目标是让玩家从主菜单出击，一直玩到结算并返回；若用户只要求做资料、地图或脚本阶段，就交付明确标记的阶段成果，不把切片、测试地图或预览说成整关。

## 开工：确定是哪一关、现在做到哪

1. 找到 Iron Tide 项目目录（有 `project.godot` 和 `AGENTS.md`），先读 `AGENTS.md`、`docs/memory/YR_CAMPAIGN_PORTING.md`、`docs/memory/YR_CAMPAIGN_MEMORY_INDEX.md`，再按索引读该关最新交接与专项规范。安装版也从项目目录找这些资料，不从技能安装目录找。
2. 核查实际目录、菜单路由、战场装配、存档入口、测试和当前工作树；不要把旧交接或未提交代码当成已发行事实。特别区分盟军 `ALL01UMD`、盟军终关 `ALL07SMD` 和苏军首关 `yr_time_shift`。注明阶段：资料／地形 → 脚本切片 → 可玩预览 → 整关验收 → 已发行。
3. 固定零售证据：版本、MIX、地图名/内部 ID、SHA-256、剧场、可玩边界、规则/美术/音轨来源、提取复跑命令。优先原图与该关覆盖，其次零售规则与实测；`refs/ts-ra2`、`refs/ra2yr-resource` 是语义与编号辅助，不是原版引擎完整证明。`.validation` 或临时目录缺失时按交接重建，不编造数据。

## 迁移硬门槛：先对照任务触发器和地图 AI

从今往后，所有战役移植与续作都以**目标关的原版任务触发器和地图 AI**为双重依据。开工先提取并分开建立两张逐 ID 对照表，再按原图接入；不能只搬地形、做主线近似，或用通用遭遇战 AI 代替地图 AI。

- **任务触发器表**：从 `Triggers/Events/Actions/Tags/CellTags` 追到实际对象、局部变量、计时、难度、启停及后续分支。核对触发和不触发两种结果，并验证玩家实际看到的行为；牵涉队伍时，继续追到 `TeamTypes/TaskForces/ScriptTypes`，区分脚本增援、招募现有单位和工厂生产。
- **任务驱动表必须接入正式战场（强制）**：凡战役任务移植或续作，正式出击入口必须加载并推进本关可执行的任务驱动表。以目标关原图为准，让原版可达的任务触发从表读取条件、计时、启停和分支，再由战场适配器执行剧情、目标、增援、胜负及特殊动作。关卡专用代码可提供事实查询和动作适配，但不得绕过驱动表硬编码整条流程充作移植。只交资料或阶段切片可以注明范围，不能当正式任务验收；只提取、导出或在测试夹具里跑通不算正式接入。
- **驱动接入必须可验证**：逐 ID 记录正式入口、触发或取消条件及玩家可见结果，从战役菜单出击用实际操作核对；独立进程冷读关键断点，验证任务计时、已执行动作及待执行动作不会漏发、重发。未支持、未接入、未验收或可达性未确认的项分开列，不以占位动作、静默跳过或普通 AI 替代；正式任务驱动接入和地图 AI 是两个独立验收项。
- **地图 AI 表**以目标地图实际用到的 AI 为范围。逐条反查本图任务及本图私有 AI 条件引用的 TeamType，追到 TaskForce、ScriptType、房号、难度与航点。按唯一编组 ID 去重，标明预置招募、脚本增援、运输、驻军、巡逻或工厂生产。只有定义而无使用来源的项目单列。继承 AIMD 的全局开关另存参考清单，分母与本图小队独立。
- 连续接入按用户指定的当批任务数量推进。优先在原图条件下能执行的队伍，按实际命令校验人数、房号、路线、难度差异、取消和读档。旧近似首次转表与首次新增行为分别说明。
- 每批交付两行覆盖数字。任务触发器与地图 AI 各写本批正式新增、累计、原图总数和剩余，保留每条稳定 ID、出击入口、执行证据和未满足的条件。全局开关、脚本增援和工厂 AI 分别追源，核实房号、实际队列、扣费、出厂与命令。原图缺少前置设施时保留禁用条件，登记夹具提供的前置。
- **两表分别验收**：每条注明原版可达性、实现状态、验证证据及剩余差异。明确区分已取证、已导入、已接线、已实测；默认禁用、不可达或无法确认的分支单列，不擅自启用，也不算通过。交付分别报告两表的覆盖率；两张表都没验完，不宣称原版整关移植完成。

## 实作：按玩家流程做可追溯清单

- **原图与脚本**：逐项串联 `Triggers/Events/Actions/Tags/CellTags`、`TeamTypes/TaskForces/ScriptTypes/AITriggerTypes`、航点和局部变量。表内写 ID、房号、难度、初始启停、触发条件、来源与目标、顺序、重复、取消、异常分支、玩家可见结果及验证方式。区分任务触发器与 AI 条件，区分定义存在与玩家可达；未知动作、越界链接、未支持语义必须显式留下，不默认为成功。出场、集合、抵达、出击和交火分别验证；游戏秒注明计时起点与单位。
- **地图、桥和坡**：先读 `YR_SLOPE_PORTING.md`、`BRIDGE_PORTING.md`、`TERRAIN_PORT_GATE.md`（均在 `docs/memory/`）。逐格比零售剧场 TMP 类别、格高、坡向、子块与调色板；检查坡底、坡顶、邻地路缘车道、原始边界、矿区和城镇、局部光照及雾。逐座清点高/低/断桥、桥头、引道与维修设施；逐端走通路线，查桥上桥下、遮挡、全跨段阻断、损毁连锁、修复与冷读。任务桥建筑和通用桥面各自验收；平面重采样、通用桥和单层寻路等近似不能当原版等价。
- **地图覆层必须单独验收**：从零售 `IsoMapPack5`、`OverlayPack/OverlayDataPack`、`Structures` 和剧场 TMP 分别核对格坐标、类型、帧、格高、坡向及边界；地形逐格无差异不代表围栏、墙、矿、桥片、小屋及任务障碍已进战场。按原图保留门洞与边界缺口；开场和每次切换时代分别核对障碍实体、连接图、碰撞、寻路、碾压/摧毁及是否计入任务目标。实车逐桥逐端上下桥并测试桥下路线，记录正常命令、夹具移动、自然游玩的区别。断桥/已修复桥及已毁障碍分别独立进程冷读，核对层级、通行和不会复活。用游戏实际加载的贴图做接缝扫描，有头同机位复核告警；未经同意不能开窗口，交付时列待验点。不要用向旧档补种地物来混同新开局装配。
- 整图验收同时记录原图总数、可玩区内数、界外裁剪和初始已毁数。建筑及中立设施逐实例核对地基、血量、房号、驻军与占领能力；对比原版房色和玩家涂装规则，战场实体、雷达、雾中最后目击、换场及读档分别验证。地形逐格重解原图，另外按 [Terrain] 逐项核对树木、标志、路灯、矿树的剧场贴图、落点与界外裁剪。矿树核对矿区系统的实体归属，冷读复核数量。桥梁同时清点普通覆层与任务建筑桥，给每座桥列出端点、可通行层、原始断口、损毁及修复方式和实车证据。优先用无头战场断言、坐标差异和存读档日志取证，尽量少截图。确需画面确认时只取能区分问题的机位，并按用户要求决定是否开窗。
- 地图重烘时，从目标原图读取日光、地面光、高度增量和 RGB 色调。对海崖检查原 TMP 延伸像素与相邻水面。用同一版地形检查器比较修前修后的坐标、组数和格数，再独立复烘一次，核对交付 PNG 和正式出击实际加载的纹理像素。原图只有任务桥建筑时，按放置、附着对象、原始断口、连锁损伤和读档验收；有普通桥面时再验分层通行。
- **预置建筑不得错位**：以零售 `Structures` 的原始格坐标、房号、朝向和对应 `artmd.ini` 地基尺寸为依据。明确区分原图地基角点、运行时中心、贴图原点和碰撞底盘，按本图坐标轴变换统一换算，矩形地基和大小写 `X/x` 都要覆盖。预置建筑禁止走玩家建造格吸附、通用找空地、按距离去重或静默挪位；碰到贴图或通行差异要定位原因，不能靠移楼掩盖。全图逐条核对可玩区建筑的类型、位置和唯一实例，保留原图裁剪边界；另验建筑与围墙/门洞/道路、工厂出入口、任务航点、资金箱的相对位置。画面、碰撞、寻路、点击命中、血条和目标标记分开验证。动态生成建筑和时代切换另查落点，从实际战场复测关键样本，并区分新开局修正与旧档迁移；未经同意不挪旧档对象。
- **阵营、AI、生产**：逐房核对归属、外交、房色、雷达、建造与产兵，验证转属、驻军、警戒、心控/解放、命令完成及难度分歧。开场按真实命令让队伍到集合点并完成第一步。区分预置、地图增援、招募现有军队和工厂出兵。用工程师占领实际设施，检查从下令、到门到转属；实点指令甲板，覆盖正确页签、科技前置、扣费、排队、出厂、失厂刷新。不要删前置、塞建筑或套用通用敌方资金/获胜规则来制造通过。
- **美术与中文**：本体、炮塔、特效、声音、生产卡、动画层与特殊单位状态按本关实际定义查。新增或重烘同批做高光：体素核对 VPL 法线、朝向、双倍贴图，SHP 保留原画明暗并核对双倍细节页；实际战场加载。房色与识别描边分开（己黄、友白、攻击目标红）；未选中移开鼠标也查。新增单位交付带中文名的全员实机截图。目标、卡片、台词、字幕和按钮用自然中文，按实际资源标明支付或免费。
- **CG、语音与雷达**：从 `Basic`、任务动作、`evamd.ini`、`soundmd.ini` 追到实际媒体。分别验战前、战中、战后、全屏与雷达小窗、字幕、短片后的续音、自然结束与跳过、倍速时画音进度和交还操控；续音中途截完整窗口。测试目标点公开/隐藏、雷达供电/干扰、标点/闪烁/回跳、镜头与小窗输入穿透，不泄露迷雾内未公开目标。CG 收藏/结算标记按既有规则，不能以解锁成功代替战场播放成功。
- **胜负和存档**：覆盖正常胜利、全灭、任务专属失败、中断/提前达成分支；从真实出击一路验到返回。检查摧毁来源、失去基地车或关键单位、占领/角色死亡、任务计时与收尾。关键阶段、转属、增援与连续影片之间（前段回调后、后段挂载前）分点写档，独立进程恢复，再继续打到终局；目标、触发、生成、语音与奖励不重发不漏发。脚本动作确认及世界副作用应在同一保存边界或使用幂等令牌。

## 容易漏掉的分支回归

- **科技中立设施与任务建筑要验效果，不只验外观和占领**：逐一串联原图 `Structures` 房号／标签、`rulesmd.ini` 默认值、地图同名覆盖及运行入口。核对工程师到门、治疗/维修对象和节奏、现金与一次性费用、秘密实验室解锁、超武、驻军、雷达与语音。验未占、刚转属、易手、毁坏和冷读；建造特权逐项测目录、请求、扣费、就绪、选址、交付和失去前置，不能只把生产卡点亮。
- **支线按标签及事件类型接线**：逐个区分靠近、发现、进入格、受袭、全灭和夺取；同一任务显示位置不等于触发对象。测试走近但不触发、误打无关目标、打中标签对象、同时销毁、重复与读档。房色分开核对占领前后材质、雷达和识别描边；语音要查事件入队及实际音轨，CG 要将触发时点、回调、片段及收藏分开验，不能用音轨存在或字幕出现代替播报。
- **玩家改变造兵顺序时，不只测默认路线。** 对「先造／后造／不造／失去」关键设施分别追脚本：记录事件是建成瞬间还是已存在，哪条旗标会锁存、清除、启用替代队，何时计时，前队卸载／返航／被击沉／全灭时下一队怎么走，末队是停止还是循环。用真实旧存档的隔离副本重现卡住的分支；检查替代队不是只生成，还会按条件继续运行。不能只关闭被取代的那支队。
- **运输与超时空分别验证到落地。** 检查入场点、集合点、卸载点和返航点，不把地图外出生点当可行驶目标。每艘运输艇验混合载员全部下艇、后续载员不被堵住、能接令并交火；岸边被挡、无合法落点、载货被击沉、途中冷读和玩家手动卸载分别查。传送则验镜头先看到落点、每组落点确有实际加载的光效与声音、不会漏播或重播；生成单位不是特效验收。
- **混编基地按实际设施给目录和权限。** 验无建造场、仅一方建造场、另一方基地车未展开、两方都取得、换边／失厂和旧档。除了切换与卡片显示，还直接检查请求、选址、就绪交付和已付队列；不能绕过 HUD 造另一阵营建筑，也不能让失效队列卡住剩余基地。仍保留原图科技、工厂和前置条件。
- **AI 与清剿都要验证玩家看得到的结果。** AI 至少按「条件成立 → 实际下单扣费 → 出厂集合 → 走到目标 → 交火」逐步取证；预置守军不算 AI。清剿阶段从当前胜负判定共用目标来源，核对战场与小地图、迷雾公开规则、被毁／转属撤标和旧档，不只发一句「消灭剩余敌军」。查电台与战报是否对同一句重复记日志。
- **交控门槛**：必须另跑一次不跳片头的正常流程；自然完成和跳过按钮可能在不同帧触发，旧影片节点尚在队列中时不可挂同名后片。直至首条玩家命令生效，记录每段可见提示和最长无媒体锁控时间；任何静默长等都要在交付前定位。
- **废案与漏接分开。** 将原图可达但项目未接的媒体、零售定义存在但不可达的分支、只剩资源无直接调用的录音分开记。提取后留原始键、文件、哈希和已核对的调用链；按原图接回可达事件。给孤立资源补触发时明确是新增设计，不伪称找回原触发，也不擅自改变胜负或奖励。

## 验收与交付

- 每次更新任务驱动表，按原图唯一触发器 ID 报告本批新增、累计入表、原图总数和剩余未入表数。多批连续更新时保留每批数字，同时说明正式战场已验证的分支和仍用代理的部分。
- **每批播报触发器进度**：报告本批核验条数、新补接条数、累计已核验与剩余待核验数，并列出完整验证、部分接线和已知缺项。旧实现复验、表驱动改造与新增动作分别统计，不重复扣减。

默认 Godot 无头、独立用户目录、隐藏控制台；需要有头验收和截图先征求用户同意。用真实菜单、Battle/HUD、autoload 和存档，不拿只 `load()`、数据审计或单元夹具冒充玩家流程。夹具推进计时、摆位、预充能、造伤害和自然游玩分别记；未做有头、独立进程恢复、发布包或整关游玩要明说。复用 `tests/` 对应关卡与桥坡、生产、雷达、CG、存档回归，不能仅以退出码判断：核对断言、stderr、截图及日志覆盖范围。避免改玩家存档和覆盖并行改动。

### 整关完成的硬门槛

- **CG 收藏节选必须与正片同批交付。** 每段新接入或换源的战役 CG（战前、战中、战后）都要从该段实际正片选取清晰、有代表性的一帧，用相同影片 ID 登记到收藏卡片并记录来源与取帧时间。不用黑场、其它影片或占位图替代。通过真实 CG 收藏页逐片核对：未收藏仍显示雪花、不可回看；已收藏（含既有收藏记录）显示对应节选，点击可回看同一段正片，无须重打或重复发奖。加入回归，防止已收藏却因漏配而退回雪花。回看进度条要实际能向前、向后拖动，画面、原声、独立音轨和字幕跟随同一播放位置；有留帧续音的片段要验拖入、拖回和片尾返回。进度条只用于收藏回看，收藏验收不替代战场播放验收。

- 把**能出击、某段能推进、旧存档可续到结算、零售整关完成**写成不同状态。必须留一条从新开局出击、用实际命令和自然计时走到胜负/返回的证据；旧档、加速、直接转属或注入伤害只计断点/分支回归，不替代新开局。每个零售环节标明「对齐、近似、缺失、未验」；有近似或缺项就不要称原版整关已完成。
- 截止点不得靠「试玩结束」或占位目标冒充后续实现。对阶段门槛逐一查触发器的**启用源和单位**、计时起点、难度掩码、局部变量、房号条件、取消链。多个计时字段不能凭相加当真实秒数；原动作按时间顺序验，出兵、到达、交火、全灭分别记。新条件要用旧真实存档验证可续、不会跳过或重复生成。
- 每次穿越/换场列出应保留、撤掉、转属、重建的单位、建筑、队伍、迷雾、桥、雷达和可玩边界；只换两栋建筑不能标成完整换场。脚本角色阵亡的替代方案要走到实际完成目标（舰载机击杀也要验），仅看到援军不算通过。
- 开场首帧检查战场实体装配后迷雾和电力已刷新，再锁控；验证全屏转雷达、留帧续音、自然结束/跳过/异常解锁都能交回操作，HUD 有持久目标，不能只检查播放器创建。旧档的缓存色不能盖掉归属：验普通和双倍贴图的索引房色、实际材质、现场转属以及独立冷读。

去掉「试玩」字样、改菜单标题或合入源码，不等于整关通过或已更新发行包。交付时说明玩家如何启动、旧档可以从哪一阶段继续，以及哪些演出或已发生的事件不会补播。
