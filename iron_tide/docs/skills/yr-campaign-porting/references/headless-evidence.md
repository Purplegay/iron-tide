# 无头取证与失败分流

## 开跑前

优先复用本关 `tests/` 的入口，Godot 隐藏无头，独立 APPDATA；seed/cold 共用一份专用隔离目录，其它试验分开。采用 `Start-Process -WindowStyle Hidden` 重定向 stdout/stderr 并设超时，必要时只清理该测试进程。加速批跑关闭测试用自动存档及定时检查点，不改玩家设置。不把有渲染告警、其它脚本编译报错、日志中断或回归未运行当通过；保存用例完成标志、退出码、断言、stderr 和逐 ID 行数。

## AI：先生产，再按用途验证动作

1. 从真实战场起跑，按房号、ID 和适用难度供给事实。阈值差一时不下单，刚好满足时选中；门槛为零记不适用。只隔离候选池，不伪造正式订单。分别验证实际出厂数量、正确账本扣费、接令。失厂、取消、断点与难度差异另验。
2. 开场真实设施和人工补齐设施分两组。人工补厂只证明「设施就绪时能出兵」，不证明正常局能建齐。记录人为资金、可见性、伤害或目标布置；不得绕过科技和工厂。
3. 生产可分段快进；移动、到达和交火保持固定 `1/60` 秒物理步长，缩短的是墙钟等待，不放大单步。只让被测队伍贡献伤害，避免把预置军算成 AI 产兵。按实际脚本评定：进攻移动及交火，驻防全员到岗再放入侵者，工程师实际到门占领，运输队实际卸载和接令。
4. 超时先记单位的当前命令、后继路点、剩余距离、目标类别、可见性、是否可达。沿真实路线布置适合脚本的目标再复测；如果路线本来不指向靶子，不因未伤害夹具目标判队伍失败。驻防分配不重叠的可达站位，别让整队争一个格；原指令相同但前置脚本不同要分组。

## 冷读和 CG

- **开场交控墙钟**：`res://tests/yr_opening_live.tscn -- <任务ID>` 从正式菜单出击；默认跳过全屏片头、让雷达简报自然结束；用 `--natural-full` 检查全屏自然结束，用 `--skip --hide-radar` 另跑简报跳过和雷达隐藏路径。不手动步进、不注入结束回调、不改倍速；明确是否跳过全屏片头，单独记录每段媒体、无媒体锁控空档、`world_input_enabled()` 和第一条实际命令。锁控的每段都要解释玩家看得到什么；有头需确认雷达折叠、字幕关闭等设置下仍能找到提示与跳过入口。只挂播放器不算。检查串联计时（启用后才起算）、只靠媒体完成信号、片头与后片交接、续音丢画面及读档恢复。缩短冗余计时须保留实际剧情门槛、原图驱动 ID 及已执行标志，并把移植差异写入交接。

- **真正的进程边界**：seed 从真实战场写档、退出；cold 新进程通过正式入口读取，再推进到可见结果。查旧动作没重发、待动作没漏、归属/资金/控制权正确。优先取「前片已结束但后片未挂载」「空降中」「一人已出厂其余仍在产」「计时将到但动作未执行」。
- **雷达续音**：片尾留帧、音轨不停、字幕跟随实际时钟。收藏回看拖入续音时，使用续音时钟而非已经停住的视频时间；拖回视频再查恢复同步。战场播放、收藏回看和有头观感分开判定。

从项目 `docs/memory/YR_CAMPAIGN_MEMORY_INDEX.md` 找该关「验收经验总结」和「84 条 AI 加速矩阵」。真实入口 `res://tests/allied_finale_playable.tscn`，参数 `-- --ai-id-matrix`；`IRON_TIDE_AI_MATRIX_ID` 传逗号分隔的小写 ID，`IRON_TIDE_AI_MATRIX_EXTENDED=1` 延长进攻至 3600 个固定步，`IRON_TIDE_AI_MATRIX_THIRD_READY=1` 仅第三房设施就绪夹具。冷读用 `--seed-opening-gap` / `--cold-opening-gap`、`--seed-opening-flight` / `--cold-opening-flight`、`--seed-ai-queue` / `--cold-ai-queue` 成对复跑。其它关复用方法，不能直接复用《脑死》的场景、航点、阈值或统计结果。
