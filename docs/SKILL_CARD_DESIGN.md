# 技能卡适用范围与图标规范

用户于 2026-11-05 确认：普通卡不能全部兵种通用，按使用场景区分；仍通过技能卡池抽取，同卡获得一次供适用单位共享。后续开发沿用本规范。

| 普通卡 | 允许装配 |
| --- | --- |
| 烟幕弹 | 步兵、地面载具 |
| 引擎超载 | 地面载具、飞机 |
| 聚焦射击 | 步兵、防御建筑 |
| 复合装甲板 | 地面载具、防御建筑 |
| 空尖弹 | 步兵、飞机 |
| 排水抢修 | 舰船（不含海豚、乌贼） |
| 锚定校射 | 有舰载武器的舰船（不含航母、海豚、乌贼） |
| 掠翼机动 | 飞机 |
| 巡航瞭望 | 飞机 |

v0.25.77 按用户要求补充海军／空军普通卡：保留原五张，再增加以上四张。它们均可抽取、按 0～3 级培养，同名只获得一次；普通品质总概率沿用原卡池设置。`excluded_units` 用于类别内排除，`requires_direct_weapon` 排除没有直接武器的载具；`scope_note` 必须与实际过滤一致。

`data/skills.json` 的 `allowed_categories` 定义类别，`allowed_units` 定义精确兵种，后者优先。范围约束共用 `rules/skill_scope.gd` 与 `UnitSkillLayout.compatible/normalize`，不能仅在下拉列表隐藏。飞机分类优先于工厂／兵营页签；海军单列，不自动算地面载具。防御建筑须确实拥有武器或驻军武器，不能把围墙、超武及非战斗建筑一并放开。收割者部署形态沿用原单位技能，不再多装一套建筑卡。

所有新增可抽卡必须配置 `scope_icon`，主轮廓先表达应用场景：车＝载具、飞机＝空军、人＝步兵、塔＝防御建筑、闪电＝电磁、晶体／六边形＝高科技、船＝海军、对空箭头＝防空、炸弹＝爆破、双炮＝重装。未来坦克／幻影的相位类使用高科技，磁暴类使用电标识。按最新确认，颜色统一表示品质：传说黄、史诗紫、稀有蓝、普通白；效果小标放右下，多类型另一类型放右上。仅 `allowed_units` 恰有一个兵种的卡算专属并保留星标；多兵种限制卡归“多单位”，仍有培养／装配入口。不要用随机颜色表达技能品质。

图标只是说明，不是权限判定。卡池、升级、单位装配、战斗 W／被动复用图标源；动态 0～3 级说明明确列出适用对象。新卡还需同步演示、等级成长、冷却、装配过滤、获取与存读档验证。

演示入口名单、数量与当前 `MetaProgress.skill_draw_candidates()` 共用来源，禁止另设手工名单过滤新卡；表现按稳定卡牌 ID 匹配，不能把下拉框排序当作动画编号。解锁类卡的门槛直接读取配置，不显示无意义的 0% 强度。新增特殊机制仍需接入对应演示动画并验证四档等级，不能以自动出现在下拉列表代替完成演示。

变更适用范围时保留已经获得的卡与培养等级，不删除所有权。新装配和新战斗过滤不适配组合；已有战斗存档的历史结算值不得未经批准重写。建筑卡必须接通实际开火／受伤、W 按钮／快捷键、运行状态和冷却，不可仅显示可装备。驻军建筑必须验证乘员武器与撤出入口。

验证采用无窗口或不切换的独立桌面；`tests/skill_scope_regression.gd` 检查分类矩阵、当前全部卡的场景图标、实际建筑伤害、经典模式隔离与存档。所有新适用类型都需要正反例，图标生成通过不能替代视觉核验。
