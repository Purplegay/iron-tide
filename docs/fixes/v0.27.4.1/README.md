# v0.27.4.1 · 多家电脑连续对局卡顿

直接查看了 15:12 启动的原游戏窗口，扩展模式、3 家电脑、1 倍速，苏联车厂排了 15 辆天启。后台采样 21.14 秒，同一游戏线程累计消耗 21.00 CPU 秒；句柄保持在 597，私有内存变化约 52 KiB。现场证实有一条线程持续接近满载。现场没有可用的逐帧呈现数据，下面的脚本耗时与慢帧数据来自隔离副本。

槽位 1 于 15:19 保存，SHA-256 为 `3C2EEB68A3EC3636071788EADE76A5117E42D74BB760AF19AA9B301670F847BC`。读入时 146 个单位，其中 100 个动员兵。连续推进 7200 个固定物理帧，在第 6000 帧另取 193 单位的中盘快照。旧逻辑继续运行出现过 729 毫秒单帧，同一快照重开后也出现过 549 毫秒单帧。新开进程的前几秒不足以验证这类卡顿。

在隔离副本中，电脑一次给整波部队查找敌人、规划路线，部分单位在首次追击时重复计算相同路线。现在每家电脑把该波进攻指令分帧下达，派令前复核单位状态，保存和读取时保留待派单位。单位复用刚确定的追击路线，武器先排除射程外目标，再做开火资格和墙体判断。尤复地图按地图标识、格距和网格尺寸缓存静态地形，每次重建从独立副本重新叠加当前障碍。电路板地图 49,284 格的陆地、海军、两栖、重碾网格分别核对哈希一致。

在包含 v0.27.4 功能的同一工程基线上，用相同的 193 单位快照、同一随机种子、独立用户目录进行无窗口对照。每 300 帧分段，共 1200 帧；机器负载会影响墙钟时间，派令时序也会改变后续战况。最大单帧从 539.0 降到 91.8 毫秒，最后 300 帧的中位数从 46.7 降至 36.6 毫秒，P95 从 68.1 降至 54.2 毫秒。独立重复四次刷新相同战局的通行网格，单次从 42.8～44.5 降到 3.2～3.8 毫秒。上述数值是无窗口回放耗时，尚未测得玩家窗口或 3700X 的修复后帧率。
