# v0.25.25.1 · 部署队友间隙绕远

2026-11-05。针对单位移动时兜圈、走冤枉路，复现并修正部署步兵之间的安全间隙被粗网格封死的问题。

## 原因与修改

寻路使用 40 单位网格。部署队友的阻挡半径已经包含移动单位半径、队友半径和 8 单位余量；填充网格时又扩张半格对角线，避免 A* 平滑路径切入碰撞体。这个保守处理会让两名部署队友之间本来安全的直线通道被误判为封闭。

现在只在有临时单位阻挡的常规寻路中增加一个直达验证：整段路线先通过地形网格检查，再逐一通过单位清距圆检查，两项都满足才返回直线。仍保留原有 8 单位余量。实际堵住的通道、建筑、水域和石块继续走原绕障逻辑；不缩小物理碰撞体、不推开部署步兵、不修改移动速度，也不修改共享地形网格。

## 复现与结果

真实 E1 步兵穿过两名部署 GGI 的间隙，覆盖水平、斜向、竖直、反向及 RA2／扩展两模式。目的地距离 600 地图单位：

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 规划路程 | 632.58～641.56 | 600 |
| 实际移动最大横向偏离 | 94.85～107.52 | 小于 0.001 |
| 新增回归 | 56 项中 16 项失败 | 56 项全部通过 |

同一测试还把部署单位移动到直线路线上，确认仍能绕开真实碰撞体；全程部署队友不移动、不受伤，静态地形网格不变。

回归共 440 项通过，脚本错误为零：deployed_gap 56、deployed_traffic 280、ground_control 52、traffic 52。覆盖部署前后改变路线、建筑夹道、战斗要塞绕行、不碾压队友、驻守不让位、双向混编队伍通过窄口，以及 50／100／200 单位完成移动。

用户截图本身不能还原完整对局路径，本次证明并修复上述同类原因，不宣称已消除所有拥挤、追击或载具转弯场景的绕圈。实际操作观感仍为 pending_user_visual_confirmation。
