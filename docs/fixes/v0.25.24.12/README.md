# v0.25.24.12 · 持续行军慢帧

持续行军仍存在逐帧工作，上版的框选和下令优化不能消除它。本版保留两项经过对照的改动：

- `scripts/units/local_traffic.gd`：缓存候选仍按原来的 0.1 秒刷新，并实时读取位置。先用实际间距、前方通道筛去不会产生分离、让路或迎面避让的候选，再读取阵营、存活、装载和命令状态。未改变碰撞、让路半径、物理频率或移动速度。
- `scripts/core/iso.gd`：三层软阴影共用一份静态三角网格。保留三层各 24 个顶点和原透明度，减少逐帧多边形提交与三角化。投影、尺寸、位置与透明度仍实时变化。

## 渲染实测

Godot 4.7.2、GL Compatibility、RTX 5060 Ti，专用隔离桌面，无用户桌面窗口或焦点切换；固定 60 Hz 模拟步进、关闭垂直同步。使用同内容快照，只替换上述两个脚本，最终源码 SHA-256 与被计时的候选一致。

`tests/march_performance.tscn` 在 4000 地图生成步兵并连续发出四段移动命令。保留战场、HUD、迷雾和原始建筑，暂停 AI 生产、禁用单位交火，以隔离行军开销。每段 180 帧，去掉前 10 帧后，每轮统计 680 帧；每个版本／规模各运行两轮，顺序为旧、新、新、旧。表中数字为两轮统计量的中位数。

| 选中步兵 | 中位帧耗时，旧 → 新 | P95，旧 → 新 | 最大帧耗时，旧 → 新 |
| --- | --- | --- | --- |
| 20 人 | 13.11 → 11.95 ms | 19.38 → 18.67 ms | 32.54 → 31.90 ms |
| 60 人 | 26.22 → 23.01 ms | 33.46 → 30.49 ms | 45.17 → 44.99 ms |

20 人场景实际运动人数的中位数为 20，60 人场景为 53。大编队 P95 下降约 8.9%，但最大慢帧几乎未变，不能宣称卡顿全部消除。这是受控行军场景；本地旧存档被正式入口判定为规则不兼容，没有修改原档或放宽读档门禁，因此不能把此表与之前那份 76 单位存档的 23.9／25.9 ms 直接对比。
