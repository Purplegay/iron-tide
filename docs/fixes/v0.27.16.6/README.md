# v0.27.16.6 大型遭遇战的多线程视野与待命单位更新

327 个单位、155 座建筑的同一存档，后台无窗口，1 倍速。正常时钟预热后依次采样交战、选中、移动命令各 15 秒。两次对照使用上一版的脚本快照，三次本版均使用最终战斗代码。该档后两个阶段实际选中 1 个单位。测试机为 Intel Core Ultra 5 250K Plus。

| P95（毫秒） | 自动交战 | 选中 | 移动命令 |
|---|---:|---:|---:|
| v0.27.16.5 对照一 | 101.5 | 139.4 | 172.1 |
| v0.27.16.5 对照二 | 121.6 | 163.4 | 136.2 |
| 本版一 | 85.6 | 104.5 | 112.0 |
| 本版二 | 98.6 | 100.4 | 127.3 |
| 本版三 | 87.1 | 164.3 | 140.7 |

每组测试均未达到整局 P95 30 毫秒。新版本各段模拟时间／实际时间约 0.98～1.01。本轮没有 Ryzen 3700X 实机及 GPU 帧耗时测量。[分阶段原始数据](measurements.json)

- 至少 128 个单位时，主线程收集各同盟的视野点和半径。至少 24 个视野点的同盟在三核及以上设备使用 Godot 工作线程，每个任务独占一张 CPU 遮罩。线程运算期间主线程处理离开视野的延迟。发布可见目标、更新纹理之前收齐本次结果。独立测量用该档两个同盟的 141 和 168 个视野点，交替执行，去除预热后各 15 次。串行与线程池的中位耗时分别为 1.243 与 0.774 毫秒，像素逐字节一致。[Godot 线程安全边界](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html)
- 大规模战局中，电脑无命令、静止待命且没有目标时，将常规索敌间隔从 0.32 秒调至 0.64 秒。可反击的单位受击后立即唤醒索敌。地面单位没有目标或移动、巡逻命令时跳过追击判断，仍执行实际让路、海面校正、特殊碾压、冷却与状态计时。
- 电脑在同一次采购决策中复用各候选兵种面对当前敌军的克制评分。兵种数量随成功入队逐项更新，预算和生产资格按当时状态检查。补矿车时先按生产表排除无关建筑，基地防守使用本家建筑坐标快照计算最近威胁。
- 七组回归 1503 项，1499 项通过。包括并行与串行视野对照、待命电脑受击唤醒和玩家索敌频率。四项平局结算存档断言在上一版也单独复现。已测通过的移动交通场景与这份持续交战存档分别计量。
