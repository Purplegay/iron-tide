# v0.27.11 · AI 按帧调度与寻路

所有电脑盟友和敌人共用一份按渲染帧计算的额度。正常负载允许 128 个不同单位进入调度；沿用战斗已有的持续慢帧检测，按档位减到 64、32、16，恢复后升档。同一单位本帧的下令、选敌和寻路共用一个名额。单次尖峰不会立刻触发降档。玩家仍从原指令入口即时下令。

排队单位在下一帧优先获得名额。有更多等待者时按入队先后继续分帧，同一单位在等待期间的新移动或攻击命令替换旧命令并保留原队位。存档保留待下发命令及其目标；读档后恢复，死亡、换边及失效目标按实际状态过滤。暂停期间不推进积压指令。

覆盖部队集结、进攻、回防、运输与战术调度，以及自主扫描敌人、追击重算、地形变化、解堵、矿车和维修车辆的路径规划。结算伤害、冷却和沿既有路线移动继续按战斗时间推进。F8 性能快照的 `ai_dispatch` 记录当前上限、本帧已进入的单位数和等待单位数。

## 验证

- 168 个 AI 单位、两个电脑席位，共用 128 个名额；验证第 129 个等待、改令保留位置、老队员优先、玩家即时下令、排队时死亡、暂停、存读档和空出名额后继续寻路。9 组无窗口专项共 1221 项通过。
- 槽位 3 副本后台回放 480 帧。三个电脑席位，回放结束时战场有 333 个单位。四档峰值分别达到 128、64、32、16，逐帧计数均在对应额度内。
- 槽位 2 副本，249 个单位、97 座建筑，1 倍战速。独立桌面上同一份代码交替启用限额和放宽限额，各回放两次，每次约 10 秒。启用时平均 14.8／17.8 FPS，P95 为 125.0／109.1 ms；放宽时平均 11.9／9.8 FPS，P95 为 153.7／158.8 ms。启用后的最慢帧分别为 386.8／349.4 ms，重战仍有顿挫。
