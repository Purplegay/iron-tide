这一轮三个阶段分别降低约 6.6%、11.6%、17.1%。仍未通过 P95 <30 毫秒的性能门槛，也没有达到 20 毫秒目标。它是同机同档的一轮实时时钟对照，不是固定录制输入，战斗进展和运行环境会带来波动。新版模拟时间与墙钟时间比约 0.996～0.997，没有改变 1 倍速推进速度。此处为 CPU 无窗口数据，不是 Ryzen 3700X 或 GPU 实机结果。[原始数据](measurements.json)

- 建造候选点：先用原生矩形与圆距离排除不可能接触的树木、矿点、单位，再做原有精确多边形碰撞。边界接触保留，未缩小碰撞体或放宽建造条件。
- 同一次电脑决策复用建筑定义提取出的占地形状。定义改变时重新计算，完成本次决策后清空。
- 同一次电脑采购复用本家的工业工厂折扣，包括没有折扣的情况；步兵价格不受影响。落下一座建筑时立刻清理本次缓存，下一次采购重新检查。
- 原单电脑入口与多方独立经营入口共同使用短期决策缓存；没有延长出兵、生产、矿车或玩家命令的更新间隔。矿车统计中的阵营型号只解析一次。

验证覆盖碰撞边界、不同占地、同 ID 修改定义、工业工厂出现／失效和不同阵营价格；并运行 AI 生产、出兵、经济、多方经营及建造范围回归。七组共 1151 项断言全部通过；其中碰撞筛选覆盖 8,000 组圆与占地，缓存覆盖 144 次实时选址及同 ID 定义改变。同档 1,440 个候选点优化前后返回结果完全相同，三轮整批校验中位数由 88.621 降到 80.416 毫秒。[回归记录](regressions.json)
