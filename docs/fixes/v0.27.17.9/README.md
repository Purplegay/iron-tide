# v0.27.17.9 · 维修进出站与大型存档卡顿

## 实际问题

用户提供 `C:/baidunetdiskdownload/slot2(1)(1).itsave`。载入后有 350 个单位、215 座建筑、六家参战方，初始 21 个单位处于维修或离场过程。使用存档副本复现，没有改写原档及玩家用户目录。

邻近的矿场、天气控制机、防空建筑会挡住维修入口或最后离场位置。原先直接朝固定点行走，无法绕过邻近建筑；等待车辆又共用站位，拥堵时不断重试寻路。维修并不是整体掉帧的唯一来源，单位更新、迷雾及建筑动画检查也占用 CPU。

## 改动

- 新增 `repair_access.gd`，按地基版本和车体半径缓存可用入口，实际碰撞检查避免粗网格把可通行入口误判为封闭。
- 进站最后一段使用有数量上限的建筑角点绕行；仍与其他建筑、车辆碰撞，仅当前维修厂允许平台内通行。
- 等待队列分配独立站位，到位后不重复寻路。离场容差避免卡在出口最后几像素。
- 队首或入场车辆连续 8 秒没有有效推进且尚未到维修点，释放占位，对该维修厂暂缓重试 15 秒；建筑布局变化可立即重试。车体确实过宽时不强行穿模维修。
- 读旧存档时重新核对维修入口。新增路径、候位及失败缓存只存在运行时，不改变存档格式。
- 不可见建筑跳过动画层逐帧指纹扫描，动画时钟继续推进，重新可见时刷新；生产、维修和战斗继续更新。
