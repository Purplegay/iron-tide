# v0.27.11.3 · 大部队寻路与覆盖存档耗时

槽位 3 的 F8 快照来自 v0.27.8.2，当时有 330 个单位、111 座建筑，最长一帧 1958 毫秒。快照记录帧间隔，无法单凭它断定这一帧的具体操作。用同局存档在较新版本分别复现了恢复战斗时集中寻路和覆盖存档时的停顿。

- 部队前往同一目标格时，附近单位可以接入已验证可走的路径，各自保留精确终点。地形改变会使旧路径失效，临时单位障碍和受搜索步数限制的请求独立计算。缓存最多保留 128 个目标与移动类型组合，每个组合最多 4 条路线。
- 当前格式读档跳过历史版本指纹计算。覆盖存档时，先验证快照，再把临时文件逐字节对照后替换；成功后仅刷新该槽位的摘要。保留旧档迁移、上一份有效备份及损坏检查。

## 槽位 3 实测

回放使用存档副本、1 倍速和独立后台桌面。恢复时 325 个单位、111 座建筑。在 v0.27.11.1 矿车逻辑上依次测试原寻路、新寻路、新寻路、原寻路，每次约 10 秒。

| 指标 | 原寻路，两次 | 新寻路，两次 |
| --- | --- | --- |
| 平均 FPS | 8.9 / 9.1 | 11.1 / 10.4 |
| 中位帧耗时 | 99.5 / 100.2 ms | 75.3 / 76.0 ms |
| P95 帧耗时 | 224.0 / 225.9 ms | 168.0 / 181.6 ms |
| 最长帧 | 489.7 / 523.5 ms | 368.6 / 429.6 ms |
| 推进的对局时间 | 8.25 / 8.30 s | 8.97 / 8.97 s |

另在三个手动槽位都有存档的副本上单次对照，打开列表从 841 降到 732 毫秒，覆盖槽位 3 从 1999 降到 717 毫秒。重战仍会出现约 0.4 秒的慢帧。此次回放覆盖读档后十秒。

最终 v0.27.11.3（含每家 AI 的 64 名额调整）另回放一次，平均 13.3 FPS，中位 62.5 ms、P95 161.2 ms、最长 364.4 ms。打开三个手动槽位的列表用时 665 ms，覆盖槽位 3 用时 658 ms。

回归覆盖共用路线、临时障碍、断路、步坦通行、海军寻路、备份和独立进程冷读档。玩家原始槽位 3 的 SHA-256 在验证前后一致。
