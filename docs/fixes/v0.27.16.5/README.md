# v0.27.16.5 尤复移动与绘制对照

尤复的逆向接口显示，每个可移动单位保存当前格、目的地、后续方向序列、路径延迟和堵塞计时器。地图格保存本格对象和桥层对象，并提供局部重绘入口。它们能证实这些数据结构的存在。原版在相同硬件、相同战局的 CPU 耗时没有实测。[YRpp FootClass](https://github.com/Ares-Developers/YRpp/blob/master/FootClass.h) · [CellClass](https://github.com/Ares-Developers/YRpp/blob/master/CellClass.h)

本机 refs/ts-ra2 是社区 RA2WEB 重制参考。其 MoveTask 保留地面路径，AttackTask 的射程检查有单独冷却，CollisionHelper 从格占用表取候选。SearchStatePool 重用寻路节点，Minimap 记录待重绘格，ShpRenderable 比较帧号后更新。以下是 Iron Tide 的实现选择。

| 系统 | 本版改动 |
|---|---|
| 寻路 | 建筑落地只封住占地内的陆、水、两栖格。对未受影响的剩余路线，继续走原路径。整图重建或缺少变更记录时重新求路。短程搜索复用工作数组，大军的跨区静态通路可使用 Godot 原生八向网格，保留禁止切角规则。 |
| 追击与避让 | 电脑攻击使用单位正式的目标指令，重复指向同一人时保留现有路径和连发状态。追击者等候新的规划名额时可继续沿已知路径前进。大部队从附近格取得避让候选，然后按实际碰撞层、半径与相对位置判断。 |
| 交战决策 | 维修、登车之类的任务按需取敌情。普通部署步兵可以在附近格检查自己两种武器能覆盖的可见敌人，同优先级采用原有单位顺序。 |
| 界面 | 雷达矿点随耗尽、再生、坐标、探索状态或投影变化更新。屏外单位和建筑跳过相应血条与标记计算，选中单位仍可读取弹药和乘员信息。 |
| 贴图与阴影 | SHP 图集载入时计算帧矩形。绘制优先复用上次仍持有的高清纹理页。炮塔阴影只需为每个朝向记录一次非透明像素，之后可与不同车身朝向合成，保留半透明边沿。 |

独立 CPU 测试中，100 次短程搜索逐点一致，六轮交替测量。32 次绕障长途寻路在新旧两套实现中都能到达，所有路段通过通行检查。尤复天启 128 组车身与炮塔朝向的阴影逐字节一致。267 个单位的位置固定时，两种避让方式取得的候选集合在六轮中全部一致。这些均为局部测量，实战慢帧另行验收。[原始统计](measurements.json)

### 同档回放

327 个单位、155 座建筑，同一测试机，1 倍速，后台无窗口。读档预热后，依次采样自动交战、选中、移动指令三个阶段，各 15 秒。该档在后两段记录到一个选中单位，不能据此判定大规模玩家框选的开销。

| 阶段 P95（毫秒） | v0.27.16.4 对照 | 本轮第一次 | 本轮第二次 |
|---|---:|---:|---:|
| 自动交战 | 133.1 | 119.3 | 94.2 |
| 选中 | 132.0 | 119.3 | 139.3 |
| 下达移动指令后 | 141.8 | 150.5 | 148.7 |

移动段求路次数从 632 降至 293、431 次，但整帧仍约 149～150 毫秒，未达到 30 毫秒预算。另一次带函数计时的移动帧共 153.3 毫秒，包含两次物理更新。该帧电脑阵营决策累计约 64 毫秒，单位物理更新约 51 毫秒，其中交战约 16 毫秒。上述函数计时含子调用，不能逐项相加。无窗口回放只能衡量当前测试机的 CPU 工作。

局部测试的中位耗时为：短程求路 100 次约 7.9 → 5.7 毫秒；长程绕障 32 次约 177 → 55 毫秒；128 组合成阴影约 37 → 4 毫秒。九组功能回归共 1012 项通过。完整分位数、采样帧数、模拟与实际时间、微测试原始轮次见上方统计。
