# v0.29.2 — 存档 3 岸边车队脱困重试

2026-11-17 的存档 3 中，九辆 AI 车辆挤在 `(3730, 4530)` 附近的狭窄岸边；其中一辆多功能步兵车保存时已累计 173.2 秒无路径进展，战斗要塞在浅水边缘无法回岸。

高负载时，AI dispatch 和路径脱困分别分配预算。旧逻辑只在取得 dispatch 名额后登记重试，而重试队列会在后续渲染帧提前分配并移除请求；单位当帧没有逻辑更新或没有 dispatch 名额时，预留名额会丢失。多次错开使部分车辆长时间无法重新寻路。普通的低压力读档回放可能自行恢复，不能据此排除现场问题。

现在所有到期的脱困请求都会刷新排队状态，只有队首单位同时持有 dispatch 名额时才消耗本帧重试预算。保持高负载每渲染帧 4/8 次上限、同帧追赶步共用预算、过期请求清理和低负载立即执行。未改变单位数量、AI 阵营待遇、移动命令、碰撞或岸边通行规则，也未编辑玩家存档。

## 验证

- Godot 4.7.2，独立 `CodexIronTideValidation` 用户目录，headless；从原始存档复制读取，不启动或操作玩家游戏窗口。
- 同档对照：60 FPS 的测试帧步进、15 Hz 战斗逻辑、强制高负载 tier 3、450 次物理更新。`render60/fair60` 对照中改前车队仍堵塞，战斗要塞位移 0；改后车队恢复。最终专项的九辆车均在存活期间实际移动超过 60 像素，最大位移为 402.80～814.74 像素，战斗要塞移动 614.34 像素并回到陆地。死亡不代替脱困断言。随后补充了同帧重复申请保护，并用 12 项队列专项复验。
- 错峰调度可独立确定性复现：32 个申请者每帧轮换 4 个外层名额，持续 96 帧；改前 tier 2/3 均无人取得重试，改后所有申请者均至少取得 8 次重试，等待不超过 16 帧。该用例作为队列缺陷的稳定回归依据。
- 真实战局受帧相位、碰撞和战斗影响：后续以独立专项再次运行改前代码时也能恢复，不能声称存档每次重载必然卡死。存档测试证明本轮能脱困，确定性错峰用例证明旧队列存在饥饿问题。
- 新公平性测试 12 项、AI dispatch 29 项、命令切换 136 项、真实存档专项 13 项通过，共 190 项。
- 扩展检查不是全绿：`battle_inspection_regression` 的 4 项按键重映射断言，以及 `traffic_regression` 的 1 项混合编队重叠断言失败；相同隔离方式下，改前代码出现相同失败。本次不修改这些行为。检查套件还产生了已有表现详情脚本错误，不能将该整套检查宣称为通过。
- 最终源码包含同时进行的刚性车辆重复重绘优化；本次只增量修改重试入口，保留了该独立改动。测试用强制 tier 3 只位于专项脚手，正式自适应负载策略未被固定或关闭。
- 原存档与隔离副本 SHA256 相同：`BB42C2CA952869237D90183482CE93A8C4DBD788F7F01FA110BC921D93D40981`。

证据在本机 `.validation/slot3-ground-stall-20261117/`，存档专项为 `final-save/result.json`，最终队列专项为 `final-fairness/result.json`，其它专项为 `checks/`，改前对照为 `before-checks/` 和 `before-fairness/`。早期 `initial/tick/unlimited/candidate/diagnostic` 探针遗漏了 `world.paused=false`，不作为行为验收依据；有效对照为 `render60/fair60` 和最终专项目录。
