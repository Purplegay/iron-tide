# v0.25.47.2 · 英雄与单位改造位置记忆

英雄养成再次打开时优先恢复上次选中的英雄，不再强制切到最近生产的英雄。没有历史选择或该英雄已不存在时，仍按原英雄列表顺序选择第一项。

单位改造保存选中兵种、阵营筛选和“仅看有专属卡／天赋”的开关，恢复左侧列表滚动位置。右侧详情按兵种分别记忆位置；英雄详情也按英雄分别记忆。切换页签、重新创建页面及正常退出重开后恢复；购买／升级的刷新保持当前位置。

位置在容器布局完成后恢复，并受当前内容高度约束；同时触发的多次重建只执行最后一次位置恢复。离开场景前记录最后一次滚动，避免子节点已退出导致丢失。未知单位和无效筛选安全回退。

## 持久化与边界

使用 Godot `ConfigFile`，独立路径 `user://progression_bookmarks.cfg`，先写 `.tmp` 再替换。保存选择字段与滚动整数偏好，不改局外 JSON 养成存档、货币、天赋点或战斗快照。首次更新没有历史位置，按原默认状态打开；强制终止进程前尚未保存的最后滚动不作保证。

仅记忆这两个面板内部的位置，不强制更改驻防入口默认页签。选中已移除单位或更改筛选后不展示无效详情。

## 验证

共 **1243 项通过**：位置记忆专项 16 项、天赋购买专项 481 项、养成回归 746 项。记忆专项使用隔离的 1280×720 SubViewport，确保真实内容溢出形成滚动，覆盖英雄与单位分别记忆、切页、刷新、关闭前最后滚动、重建后读盘恢复、筛选持久化及无效值回退。

早期广回归发现并行开发中的磁暴线圈装卡失败；该处更新后重跑已通过。旧的“返回英雄页选择最近生产英雄”断言按本次需求改为保持手动选择，未删除验证。最终没有脚本错误；部分 UI 套件退出仍有字体／CanvasItem／ObjectDB 资源释放警告。源码与隔离测试副本一致。见 [验证摘要](verification.json)。

均使用 headless／CREATE_NO_WINDOW 和独立 APPDATA，不弹出测试窗口、不触碰玩家配置。界面观感仍为 `pending_user_visual_confirmation`。
