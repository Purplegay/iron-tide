# v0.26.2.1 · 尤复原图采矿

六张尤复地图的金矿和宝石按原始 OverlayPack 类型与 OverlayDataPack 密度生成，共 4460 格。三个战区分别使用安装包中的 12 种金矿、12 种宝石及各阶密度图像。地图中的 57 座矿钻使用对应的原版动画。

此前扩展模式将地图的一层矿当一单位资金采集，并让采空的金矿按每秒 2% 自行恢复。每块矿又以自己的起始储量作分母绘制，稀矿也会显示满矿。现在经典与扩展模式的尤复原图均按包采收，车进入矿格后连续工作，采完优先移往附近可达矿格。满载或附近无矿时回厂。金矿每包 25，宝石每包 50，超时空矿车容量 20 包，武装采矿车容量 40 包。

矿格在采收时逐阶减少并显示对应密度。天然金矿按地图的 TiberiumGrows 和 TiberiumSpreads 开关分别增密和扩散，采空后需要邻矿扩散或矿钻播种才会重新出现。冰河世纪禁用自然增密。宝石采空即止。矿钻在原图位置向附近一至两格播种。仅地形合适、没有阻挡的位置可以生成新金矿。经典和扩展模式的资金入账继续经过各自的经济结算。

**数据依据**　六张零售地图、rulesmd.ini 的 Riparius、Cruentus、CMIN、HARV 和 TIBTRE01～03，以及温带、雪地、城市 MIX 中的 SHP 和色板。格子、密度、动画素材和 INI 参数直接读取。采收节奏、末帧清除和矿钻播种参考本地 ts-ra2 的 GatherOreTask、TiberiumTrait、TiberiumTreeTrait。Godot 以 15 规则帧每秒执行，寻路与随机播种属于本引擎适配，未逐帧对照尤复可执行程序。

**存档**　保留地图文件指纹，旧原图存档按现存剩余量转换成离散矿层。扩展模式旧超时空矿车的在途货物由资金单位转为包。新档保存矿层、货物、采收间隔、矿钻与生长计时以及随机状态。

**验证**　六张地图在经典和扩展模式下逐一检查原始矿格数量、生成与存读档。另用冰河世纪的超时空矿车和陆中群岛的武装采矿车实际跨格采矿并回厂。检查满载、宝石结算、采空后空地保持、矿钻局部播种和旧档货物转换。入口为 native_maps_regression、native_ore_regression 和 auto_harvest_regression。

三套无窗口回归分别通过 174、40、68 项检查，合计 282 项。
