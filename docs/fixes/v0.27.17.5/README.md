# v0.27.17.5 · 桥面堵车修复

## 原因与修改

原版地图的桥面来自离散地块，旧交通识别只认识修复桥的矩形；原版桥没有进入桥面专用逻辑。桥上闲置单位只能横向让路，容易被河岸限制；卡住重试还会将友军暂占的格子当作封路障碍，计算出绕大半张地图的路径，随后横向闪避也可能把车头转向水边。

- 加载地图时合并相连桥格并缓存桥面范围，接入 PathService 的桥面查询，保留原通行网格和水陆规则。
- 双向通行各走右侧，桥头、拐点和目的地前 80 像素恢复精确路径转向。沿用现有车体转速与碰撞，不瞬移、不缩小车体、不改变游戏时钟。
- 桥面闲置友军优先沿桥前进让路；每一步仍检查地形和物理碰撞。固守、部署、正在作战、采矿、维修、已有移动命令的单位不被强制改令。
- 桥上堵塞保留地形路线，不对临时友军占用做全图绕行，也不使用指向河岸的横向脱困。其他区域仍保留原来的绕障处理。

旧档无需迁移，桥面数据随地图加载生成。未导出试玩包、未推送 Git。

## 后台验证

全部 Godot 4.7.2 --headless、独立用户目录，无可见游戏窗口。使用 Circuit Board 原版桥：桥面停 3 辆犀牛，24 辆犀牛分两侧相向通行。旧版两种模式各只有 14/24 在 60 模拟秒内越过目标岸线，并出现车体滞留水边；最终版经典／扩展 × 玩家／AI 命令 × 15/60 Hz 八组均 24/24；全部停稳用时分别 45.93／26.5 模拟秒，没有全图绕行，最终全部处于有效陆地。两种频率均用实际物理步长更新单位；频率改变会影响拥堵中的转向和避让耗时，不能把两档时间当作同等吞吐。AI 组使用实际 ai_order/dispatch 入口，测试期间关闭整场宏观 AI 决策，以固定通行场景。

另通过 native_bridge_traffic_regression、tank_passage_regression、traffic_regression：原版桥往返、岸边恢复、低桥海军阻挡与读档纠偏、建筑窄道、固守与闲置让路，以及 50/100/200 混合单位到达和无重叠检查。最终桥面矩阵 208 项、既有桥面 30 项、窄道 40 项、交通 52 项，共 330 项通过。完整检查结果、失败基线与源文件指纹见 regressions.json。

这是固定拥堵场景的逻辑验证，未接管用户当前窗口，也未证明任意地图、任意战斗拥堵都已消除。无头结果不等于实机画面验收；本次未宣称达到全战场 P95 20～30 ms。
