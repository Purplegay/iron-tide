### 1. C7「`_recompute_bonuses` 脏标记化」——上限 1.10 ms/帧，否决

数据源 `runs/unitwork-base/unit-work-summary.json`（K=3.43、900 步）：

| 函数 | calls | self ms/步 | inclusive ms/步 | µs/次(incl) |
|---|---:|---:|---:|---:|
| `_recompute_bonuses` | 420,937 | 0.724 | **2.047** | 15.01 |
| `_recompute_base_bonuses` | 420,937 | 0.466 | 0.647 | 4.74 |
| `_tick_skills` | 267,115 | 0.731 | 2.013 | 23.26 |
| `_tick_buffs` | 279,862 | 0.045 | 0.045 | 0.50 |

物理步 298,255 ⇒ 每单位步 **1.41 次**重算。理想脏标记只能压到 1.00（省 29%），
即 `2.047 × 0.29 = 0.59 ms/步 ≈ 1.42 ms/帧`；绝对上限（把 `_tick_skills` 那 63.5% 全部命中）
**0.459 ms/步 → 1.10 ms/帧**。低于噪声，且需给 55 个外部调用点全部打脏，漏一处即静默削弱 buff。
`_recompute_base_bonuses` 原注释已写明 "Do not cache across ticks: effects can expire ... during another
actor's attack"，即缓存本身就与注释语义冲突。

## 2026-11-19 · 正确性修复：`AlliedAbilities.source()` 接受建筑（非性能项，不计收益）

这不是性能候选，**不计入任何 B0/S 收益**，也未走 A→B→B→A 完整帧四场：它是运行时脚本错误的修正，收益口径应是"错误数"而非毫秒。

根因：`battle._capture_enemy_music_roster()` 遍历 `units + buildings` 并把每个 actor 传给 `AlliedAbilities.flag()`，进而调用 `source()`；而 `source()` 只按单位语义读取 `unit.unit_id`。建筑是 `StaticBody2D (Building)`，携带 `building_id`，于是每次调用都抛 `Invalid access to property or key 'unit_id' on a base object of type 'StaticBody2D (Building)'`，`flag()` 实际从未生效。

修法：`source(unit)` → `source(actor)`，开头按 `actor is Building` 分支改查 `GameData.ra2_source_buildings`，单位路径不变。数据核对：`data/ra2/buildings.json` 共 295 条，其中 11 条进入 `allied_capabilities.buildings`，`extra` 均无 `DontScore` 类键，故修复后建筑侧 `flag()` 恒返回 `false`（可计分），与原意一致。

**裁决：`flag()` 的额外改动已回滚。**它在工作区里被改成先 `if value is bool:return value` 再走 `_ra2_flag()`，而 `game_data.gd::_ra2_flag()` 开头本来就是 `if v is bool: return v`，属纯冗余、零语义。为让 diff 严格限定在 bug 修复范围内，已还原为原样并复验（238/0 不变）。回滚后本文件净改动 = `source()` 一处（+11/−4）。

**diff 中其余三处（SCHP 收炮起飞 `info()`、`c4_explicit` 显式爆破、`cancel()` 清 `leizhu_court_order`/`peregrine_hunt_order`）不是本轮产物**，属工作区既有未提交改动（`docs/CHANGELOG.md:109` 已记 SCHP 群体部署规则），按"不覆盖他人工作"原则保留未动。
